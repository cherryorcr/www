# 第二部分：逐参数设计理由

## 2.1 为什么用 `[L2norm(X) ‖ text_emb]` 联合空间聚类

**设计理由**：下游 student 学的正是图文对比目标，**在它将要在其中学习的几何里做聚类**，等于让构造目标与训练目标在同一个度量下对齐。

**为什么 X 要单独归一化**：X（原始特征）与 text_emb 的尺度可能差一个数量级（实测：arxiv 上 X 行模长 0.805，text_emb 归一化后为 1.000）。若不归一化就拼接，聚类实质上只由尺度大的那一侧决定。逐行归一化后 768 维中两侧各占 384 维，**权重相当**。

**代码坑**：必须写 `F.normalize(x, dim=1)`。写成 `F.normalize(x, 1)` 会被理解为 `p=1`（L1 范数），形状上不报错但语义完全变了。

## 2.2 为什么 max-min 播种（而非随机初始化中心）

**设计理由**：初始化质量是**下游方差的主要来源**。

**证据**：旧随机版跨凝聚 seed 从 **49.9 到 80.1**（std 11.74，最差 49.92）；确定性版 std≈0。**这个方差（±15）远大于任何优化能提供的稳定收益（ASM ±1.3 内摆动）。** 所以先消灭随机性，比先调优化更划算。

**为什么首中心取 `argmax(mass)` 而不是索引 0**：让最大簇成为第一个代表，符合"代表性优先"的直觉；且与 seed 无关，保持确定性。

**为什么强制种子留在自己簇**（L125）：避免空簇——若某种子被其它中心夺走成员，它的簇会空掉，实际簇数小于 k，破坏预算。

## 2.3 为什么最多 25 轮 Lloyd

**设计理由**：25 轮是**经验上限，不是主停止条件**——主停止是 `allclose(atol=1e-6)`（L132）。实测在这批数据上通常在 10–20 轮内收敛。设上限只是防止极少数不收敛情形无限循环。

**为什么用 atol=1e-6 而非 rtol**：中心在 768 维空间内的绝对漂移小于 1e-6 时，对分配已无影响；用 rtol 会因中心范数不同而给出不一致的严格度。

## 2.4 为什么 X 取簇内**原始 X 的均值**（而不是归一化 joint 的中心）

**设计理由**：均值是**簇内特征的一阶充分统计量**，最小化簇内平方误差，是"用一行代表一簇"的无偏选择。

**为什么用原始 X 而非 normalized X**：聚类用的是归一化 X（为了与文本等权），但**输出的合成特征应该与真实节点的特征同尺度**——因为 student 的图塔是在真实特征分布上被评估的。若输出 normalized X，合成图与真实图之间存在系统性尺度差。

**边界**：簇只有 1 个成员时，均值就等于那一行真实 X。所以"全合成"是构造规则描述，**不是匿名化或零泄漏保证**。

## 2.5 为什么文本要选"最近簇心的 5 篇"并重新编码

**三个决定**：

**（a）为什么选代表而不是随机**：`fuse_new_only` 按 joint 空间到簇心的距离排序取前 5。理由是**代表性优先于新颖性**——S2 消融里用 GPT-2 NLL 选"信息量高"的文本反而更差（54.17→46.99），因为信息量高不等于切题，掺进拼接文本会污染整段 embedding。

**（b）为什么是 5**：扫描 g=1/3/5/7/9，g=1（单条）约 49，g=5/9 达 53–54 且 g=5 方差更小（54.52±1.23）。**g 太小丢信息，太大则拼接后主题发散**；5 是平台起点。

**（c）为什么必须重新编码**（L164）：字符串不能平均，但 `texts` 与 `text_emb` **必须严格对应**。若偷懒平均 5 个 embedding，tensor 看上去是对的、形状也合法，但语义上对应的是"5 个文本的平均"，而保存的 `texts` 是拼接串——**图文配对就此断裂**。文本置换实验（同阶段内打乱配对，当前阶段 test 掉 **11.20 pp**）证明这种对应是有用信息。

**为什么总共 320 字符、每篇至少 48**：`per = max(48, 320//g)`。若 g=5 则每篇 64 字符。**下限 48 保证每个被选文本都有实质内容**；若 g 很大（如 10），320//10=32 < 48，此时下限生效，总长会超过 320——**这是有意为之的软上限**。截断按字符而非句边界，所以句子可能不完整。

## 2.6 为什么 DEGREE=1.0 且用文本相似度连边

**参数含义**：`count = min(int(k × DEGREE), 候选对数)`，即选全局 top-E 条无向边，E≈k。**它不是"每点 1 个邻居"**——k=121 时选 121 条无向边，平均非自环度为 2，且度分布不均匀（有的节点可能没有非自环邻居）。

**为什么不用真实边粗化**：把真实引用投影到簇级会产生**高度集中的 hub**（大量真实边汇成少数簇间连接），GCN 消息传播被少数 hub 主导。实测真实边粗化掉 10 pp（54.17→43.74）。

**为什么文本 kNN 更好**：它在**与对比目标相同的几何**里衡量"这两张卡片是否该互相传递消息"。

**为什么 degree=1.0**：扫描 2.0/3.0 在早期 native 管线上是 2.0 更好，但迁移到 GraphCLIP 派生管线后**参数需要重选**（文本空间变了）：这里 1.0 是新的最优点，3.0 时掉到 42.78。**这说明边预算系数是与文本空间绑定的参数，不能跨管线套用。**

**一个常被忽略的后果**：拓扑每阶段在**全体** memory 上重建，所以旧行的 X/text 虽然不变，但**旧节点的邻居可能改变**。"保留旧数据内容"≠"保留旧节点响应"。

## 2.7 为什么 rate=5%

**设计理由**：rate 是数据集的存储-效用权衡点，5% 是在两个数据集上验证的平台起点，**不是从理论推出的**。

**证据**：arxiv 上 1%→5% 提升明显（16.17→19.74），5%→10% **无增益**（19.76），即 5% 附近是平台；Cora/Citeseer 同样用 5%。

**为什么不再往下压**：1% 在 arxiv 上只有 16.17（比 5% 低 3.6 pp），压缩损伤已经显性化。

**后续已证伪的改进**：我们试过用率-失真决定 k，**失败**——失真的肘部（20%，k=27,094）落在 F1 平台起点（2%，k=2,709）的 **10 倍之后**，因为高维 k-means 的失真曲线没有明显拐点，而它测的是几何概括质量、不是判别信息保留。**所以 rate 保持常数。**

## 2.8 为什么新块配额是 `max(余量, 15×新类数)`，c=15

**要解决的问题**：append 的历史保持很强但**当前阶段较弱**（Cora 上 cur 48.67 vs old 75.32）。若不干预，新类在 memory 里没有足够位置。

**规则的两重含义**：
- `预算余量` = 常规情况，新块只用剩余容量；
- `15 × 新类数` = **下限保护**，保证每个新类至少有约 15 行的表现空间。

**为什么是常数 15 而不是学出来的**：预算扫描显示收益窗口**窄且非单调**（Cora：87/34 得 53.56、77/44 得 53.13、67/54 掉到 48.92、57/64 掉到 47.28）；且"质量自适应的分配器"需要**阶段内训练-评估循环**，违反协议。所以取一个**跨数据集都不损害累计的温和常数**。

**落地差异（重要）**：Cora 上 3 个新类 → 下限 45 > 余量 34 → **触发**（旧 memory 87→76 行，按 mass 删 11 行），换来 cum **+2.85**、cur **+7.61**、old **−2.05**；Citeseer 上 2 个新类 → 下限 30 ≤ 余量 33 → **不触发**，维持现状。**同一常数在两个数据集上表现不同是完全预期的**——它只在"余量不足"时才起作用。

**为什么删除按 mass 升序**：mass 小的行代表较少的真实节点，删它们的信息损失最小。

**后续已证伪的改进**：把 c 或 recluster 的取舍做成几何判据——**未通过**。recluster 在 arxiv 类别增量的**第一个阶段**（还没有旧 memory 可混合）就低 1.97，说明那是**加权聚类本身的构造代价**，与"混合"机制无关。所以大图上的动机不足，**保持常数 c=15**。

## 2.9 为什么 student 是 2 层 GCN、hidden=384

**为什么 2 层而非更深**：memory 只有 32–121 行（Cora）到 6773 行（arxiv）。**在几十行的图上，深图塔必然过拟合**——2 层 GCN 的感受野已覆盖 2-hop，对这个小图足够。

**为什么 hidden=384**：与输入 X 维度和 text_emb 维度一致，不需要额外的升维/降维投影，减少参数。

**为什么只在一层后加 ReLU**（L87）：`g2(F.relu(g1(x, adj)), adj)`——第一层后非线性，第二层后直接 L2 归一化。这是 CLIP 风格的双塔惯例：**最后一步必须是归一化**（因为相似度用内积），若在归一化后再加非线性会破坏范数。

**为什么文本投影也是 384→384**：它要与图塔输出在同一空间比相似度；保持维度可以让"投影"只学一个旋转/缩放，而不是被迫做降维。

## 2.10 为什么 logit_scale 可学且 clamp 上限 100

初值 `log(1/0.07)` 对应温度 0.07，是 CLIP 的标准初值。**可学**是因为最优温度取决于任务难度（40 类的 arxiv 与 7 类的 Cora 需要的"锐度"不同）。**clamp 上限 100** 是防止训练中温度爆炸导致 softmax 饱和、梯度消失。

## 2.11 为什么损失是双向 InfoNCE

```python
loss = (CE(logits, target) + CE(logits.T, target)) / 2
```

**图找文本 + 文本找图**两个方向。单向（只做图找文本）在早期实验里明显更差。直觉：双向让**两个塔都得到监督信号**——若只做图找文本，文本投影只作为"被匹配的对象"，更新较弱。

**为什么用对角线的 batch index 作为 target**：这是一种**自监督正样本构造**——同一行的图表示与它自己的文本表示是正例，batch 内其他文本是负例。**不使用类别标签**，这是"凝聚全程无标签"的关键。

## 2.12 为什么训练步数是 `min(2048, 16 × roots)`

**这是被一次真实故障逼出来的设计。**

早期统一用 2048 步，结果 Cora stage-0（只有 **32 行**）的 dev F1 只有约 28.7，而短训练时曾达约 70。**32 行的小图被 2048 步反复训练，严重过拟合。**

改成 `16 × roots` 后：32 行→512 步（得分大幅回升），121 行→1936 步，143 行→达到上限 2048。**每行约 16 次更新**是这个数据规模下的合理暴露量。

## 2.13 为什么 rate 之外还要区分"预算"和"文本字节"

PROTOCOL v2 §3 把预算定义为二元组 `(root_count, aux_bytes)`。原因是**只数根节点会低估存储**——文本、embedding、边和元数据都占空间，构造过程也有开销。所以"5%"指的是 **root count** 的 5%，论文中必须说明它不是严格的 5% 存储或计算成本。

# 第三部分：条件扰动模块（v1.2）的设计理由

## 3.1 为什么会有这个模块

**观察**：arxiv（169k）上，`frozen` 构造 artifact 的 dev F1 是 18.30，而**任何足够幅度的 X 扰动**都能把它提到 20.3 左右（+2.0）；小图（Cora/Citeseer）上同样操作是 −0.25 到 −8.15。

**为什么**：簇均值 X 是"过度平滑"的——它抹掉了行间差异；大图每类节点数多（arxiv 每类平均 3.4k），这种平滑最严重。扰动重新引入了行间差异。

## 3.2 为什么必须是"构造之后"扰动，且不能锚定

**锚定实验（决定性）**：给 ASM 加 proximity 锚 $\lambda\|X-X_{init}\|^2$，λ=1e-2 时把所有步数的 F1 压到 **17.0–18.7——低于 frozen 的 18.30**。漂移被锁死在 ~0。

**结论**：**收益恰恰来自"离开构造式起点"这个动作本身**，而不是"接近某个目标"。所以模块必须在构造完成后独立施加，任何把它拉回起点的项都是有害的。

## 3.3 为什么用随机方向而不是优化方向

**证据**：给 ASM 做同幅随机扰动对照——**随机扰动 +2.00（CI [+0.74,+3.31]），ASM 相对随机只有 +1.30**；在另一个独立 run 里**随机扰动反超 ASM**（rand +2.09/+2.02 vs asm +1.56）。

**结论**：ASM 的有效成分是**幅度**而不是**方向**。既然随机就能拿到大部分收益，就没必要支付双层优化的代价（50 步反传、需要 teacher）。

**同时这也重新解释了 ASM**：它的 outer 更新自发漂移到的幅度（实测 1.79）**恰好等于**幅度曲线的峰值——它做的事等价于"把 X 推到最优扰动幅度"，只是成本高得多。

## 3.4 为什么幅度是 1.79

**倒 U 形曲线**（arxiv）：0.20→−0.38、0.45→+0.58、0.90→+1.19、**1.79→+1.97**、3.60→−2.90。

**1.79 是峰值，且它等于 ASM 自发漂移幅度**——这不是巧合，是"两项独立观测吻合"的交叉验证。

**但必须写明幅度是规模依赖的**：同一 1.79 在 6,773 的池上是 **−5.14**（0/5 全负），在 13,547 上是 −1.34。**固定幅度在小池上从"过强"变成"破坏性"。**

## 3.5 为什么开关用规模门槛，且门槛是 3–5 万

**实测**：2.7 万池上两个幅度都为负（−0.60/−2.02），5.4 万池上两个都显著为正（+1.17/+1.76，4/5）。

**为什么不用更"机制性"的统计量**：**试过了，失败**。簇均值行间相似度、spread、有效秩这三个统计量在 5 个尺度上与 `n_pool` 给出**完全相同的 Spearman 相关系数**（±0.700/±0.900）——它们是规模的另一种写法，提供不了新信息。所以退回规模门槛。

**注意**：门槛的中间点（2.7 万）出现**非单调回落**，成因未解释。这个开放问题必须如实写入论文的 limitation。

## 3.6 为什么 seed 固定

**这是设计选择而非实现细节**：固定 seed 让模块**完全确定性**，与整个方法的确定性立场一致（消除凝聚随机性正是主线结论之一）。5 个不同 jitter seed 的均值落在 19.51–20.33（std 0.31），说明结果**不依赖 seed 抽签**，固定它没有代价。

# 第四部分：三个"为什么不做"的设计决定

## 4.1 为什么不优化 X（不用 ASM 作为主线）

三条独立证据指向同一结论：**ASM 的 loss 是坏指标**（所有 arm 收敛到**完全相同的 0.0078**，而 F1 差 5 分）、**锚定有害**（阻止达到最优幅度）、**ASM ≈ 随机**（跨 run 符号不稳）。

**但必须保留的边界**：ASM 在 arxiv 上相对 frozen 确实有 +3.29（CI 不含 0，5/5）。**我们否定的是"ASM 优于随机扰动"和"ASM 的方向是有效优化"，不是"ASM 完全无效"。** 这个区分在论文里必须写清。

## 4.2 为什么不用冻结模型的响应做约束

**response-retention 实验（最有信息量的负结果）**：KL 被优化到 **0.001（降 92–99%）**，说明目标完全可以优化——**但下游毫无改善**，没有一个凝聚 seed 满足改善门槛。

**理论解释（无代理命题）**：teacher 的参数里已经包含了材料看不出来的知识，所以**"冻结模型仍能给出原答案" 与 "新学生能从材料学会" 是解耦的**。11 个 artifact × 5 类预测器全部失效是这条的量化证据。

## 4.3 为什么 rate 保持常数、c 保持常数、η 保持常数

**这是本轮四条改造尝试全部失败后的收敛结果**：k 的动态化（率-失真）失败、c 的可学习化弱化、η 的统计量化失败、只有协议修正成立。

**净结论**：方法形态**已经收敛**，不需要更多可动部件。而且两条负结果本身有价值——它们解释了**为什么这个领域普遍用人工指定的压缩率**：不是懒惰，而是**几何失真与下游效用在高维下解耦**。这是一个可以对整个凝聚方向提出的观察。

# 第五部分：需要特别声明的实现边界

| 项 | 声明 |
|---|---|
| **mass 未参与训练** | `memory_to_trainable` 把 mass 作为 `weights` 传入，但 `train_student` **从未读取它**。各合成行均匀采样。`mass=20` 不等于重复训练 20 次。 |
| **评测是 transductive** | student 在整张真实图上传播，计分节点可接收无标签邻居信息。不是严格 inductive。 |
| **test 节点参与凝聚** | whole-graph transductive、label-free 地参与了构造源；只有**标签**是封存的。 |
| **prompt 在训练中出现** | 类别 prompt 作为图文配对的内容参与训练，所以"零样本"指"不使用类别标签构造分类损失"，**不等于这些类别从未出现**。 |
| **标签并非完全未接触** | 准备程序用标签划分类别阶段，dev 标签用于选模。不能宣称整流程不接触标签。 |
| **文本是摘录拼接** | 不是 LLM 生成式摘要，句子可能不完整。 |
| **memory 不变 ≠ 不遗忘** | 拓扑每阶段重建、student 每阶段重训，旧阶段表现仍会变化。 |
| **Cora/Citeseer 是开发数据集** | test 分区（`%10==2`）已消耗，最终论文需补全新数据集。 |
