# P2 后续：图条件注意力文本压缩

状态：P2-A 与 P2-B 均已在 Cora/Citeseer 小图完成正式矩阵，均未通过晋升门禁；默认仍为 center concat。P2-A 结果见 [P2-A 完成报告](P2A_GRAPH_CONDITIONED_TEXT_COMPLETION_ZH_2026-09-18.md)，P2-B 结果见 [P2-B 完成报告](P2B_STUDENT_GUIDED_ATTENTION_COMPLETION_ZH_2026-09-18.md)。

执行注：已测的是无可训练投影的归一化 query + MMR 选片，以及同片段 graph_pool；以下可训练 `W_q/W_k/V` 和有界残差仍是未执行的进阶设计，不能混称已经完成。

## 1. 与已经做过的注意力有什么区别

P2 已比较文本集合的均值、距离加权、无参数内容 attention pooling，并测试以同预算 concat embedding 为蒸馏目标的 DeepSets。它们没有通过跨数据集、独立 seed 和阶段保持的全部晋升条件。因此不能重新把“多个文本 embedding 加 attention”命名为一个从未试过的新方向。

值得新增的问题是：**合成节点要代表某个图文簇，能否根据该簇的图属性与合法局部结构，判断哪些文本片段对这个合成节点最有用？** 图结构是否提供了超出文本内部相似度的信号，需要打乱图条件的反事实控制。

## 2. 优先方案：用注意力选片段，仍然拼接重编码

1. 从当前 delta 的源簇形成图属性摘要与局部结构统计。只使用合法的当前构造源和旧 synthetic memory，不读取历史原始节点/文本，也不借用报告节点文本。

   当前节点属性本身含有文本语义，因此仅将均值 X 当 query，并不能证明利用了图结构。图条件组应显式包含合法邻接上的邻域摘要；另设去掉结构摘要的属性-only query 控制，避免把第二次文本加权误称为结构创新。
2. 源文本拆成确定性的片段，每个片段由冻结 MiniLM 编码。共同源预处理的读取量和编码成本单列，不声称整个 pipeline 只读取最后保留的 tokens。
3. 以图条件摘要形成 query，以片段 embedding 形成 keys，计算片段权重：

\[
q_g=W_q s_g,\qquad
a_{gi}=\operatorname{softmax}_i(q_g^T W_k e_i/\sqrt d).
\]

4. 按相关性与冗余约束，在固定 token 上限内选择片段；排序规则固定、空片段与并列分数确定性处理。注意力高不等于因果重要，不能只靠权重图解释收益。
5. 对选中片段按规范顺序拼接并重新编码，保留当前 student 接口。保存可读片段及其权重，不生成无来源的新事实。

这个方案改变的是“挑哪些内容”，不是同时改变节点特征、拓扑、student 和文本编码器，更容易归因。普通文本 MMR 已有实验，必须证明图条件有额外价值。

## 3. 第二方案：图条件集合表示

直接计算 `z_text = sum_i a_gi * V(e_i)`，将其作为合成节点文本目标；先试有界残差混合，防止小数据训练把表示拉离 MiniLM 语义空间。保留同一批预算内片段作为证据。

它不是“有更长可读摘要”，而是压缩文本集合的向量表示。需要额外报告聚合器参数、训练与存储成本、图文表示的尺度变化，不能把多序列 attention 和单序列 concat 当作同等计算。

若新增可训练矩阵，只能使用合法训练源建立匹配/蒸馏目标，训练与源内验证分开；不能使用 report-dev 或 test 来拟合。起步不直接对 report student F1 反传优化注意力。若将独立 selector 的 student response 用于选方案，则这是更贵的选择流程，必须计入成本。

旧 memory 的文本向量仍冻结。若聚合器跨阶段更新，需要将新输出锚定到共同冻结文本空间，避免旧/新向量坐标不兼容；第一轮优先固定聚合规则或控制参数更新，而不是顺带刷新全部旧文本。

## 4. 最小受控矩阵

| 组 | 用途 |
|---|---|
| 同 token 的 center concat | 公平文本控制，不能直接用字符版分数作分母 |
| mean pooling | 判断是否只是平滑/平均收益 |
| 已有 text-only attention | 隔离加权聚合本身的效应 |
| attribute-only query | 区分原始文本属性条件与真实邻域结构条件 |
| graph-conditioned selection + reencode | 优先候选，尽量保持现有接口 |
| graph-conditioned pooling | 第二候选，不与第一候选同时改变其它模块 |
| 相同结构/参数但打乱 graph query | 检验真正的图条件贡献，而不只是更多参数或随机性 |

所有组固定源簇、合成 X、rows、edges、文本候选源、token 上限、MiniLM、student steps/batch/seeds。字符版 v4 另作为历史部署基线，不冒充严格等 token 组。

先做 Cora/Citeseer，再用预先固定的新顺序和独立 construction/selection seeds 确认。若图条件组不优于 text-only 或 shuffled-query，不能宣称 graph-text attention 有效；若只在一个数据集或最终阶段好，也不能直接替换主线。

## 5. 启动和停止条件

优先级在本轮小图顺序/成本报告之后。启动前先核对性能缺口：如果主要问题是跨边传播或预算覆盖不足，应先处理对应机制；文本注意力仍保留为明确候选，不被永久关闭。

晋升需要同时考虑最终与阶段平均 F1、old/new、相对完整数据保留率和新增成本。阈值、候选规模与停止规则在看到新分数前冻结。负结果应完整保留，不能继续扩大搜索直到出现最好 dev 值。
