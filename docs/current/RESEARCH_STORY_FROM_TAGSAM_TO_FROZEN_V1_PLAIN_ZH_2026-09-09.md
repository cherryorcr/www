# 第一部分：先把我们究竟在做什么讲明白

## 1. 一个贯穿全文的比喻：把论文图压缩成一套复习卡片

假设有一批计算机论文：

- 每篇论文是一个节点；
- 论文之间的引用关系是边；
- 标题、摘要等是节点文本；
- 每篇论文还有一串数字特征，代码叫 `X`；
- 论文所属研究方向是类别标签，例如神经网络、遗传算法。

这就是文本属性图，英文 Text-Attributed Graph，简称 TAG。这里的 TAG 不是“给笔记打标签”的 tag。

图凝聚想做的事，可以想成：把几千篇论文整理成一小套“训练用复习卡片”。卡片不是为了给人背诵，而是给机器学习模型训练。每张卡片都有数字特征、文本以及与其他卡片的关系。

验收标准不是“卡片看上去概括得不错”，而是：

> 给一个没有学过这批论文的新模型，只让它用这套卡片训练。训练完后，它能否正确识别真实论文的研究方向？

所以，凝聚的对象是训练数据，而不是把大模型参数压成小模型参数。

## 2. “持续”增加了什么限制？

如果所有论文始终可读，每次都能重新整理最好的卡片，这是静态或允许重读历史的设置。

本项目要求论文分批到达：

```text
第一批论文到达 → 只能留下第一套小卡片
第二批论文到达 → 只能读旧卡片和第二批论文，不能回看第一批全文
第三批论文到达 → 只能读前一套卡片和第三批论文
```

每一批叫一个阶段 `stage`，当前新到达的数据叫 `delta`，保留下来的小图叫 `memory`。

因此每次更新要同时做到：旧知识不要丢，新知识也要放得进去。这两种要求分别叫“历史保持”和“新类塑性”。

这里持续保留的是小图，不是同一个 student 的模型权重。主要验收仍然是每个阶段拿导出小图，重新训练一个独立 student。这样测的是小图本身的训练价值。

## 3. 先认识几个经常出现的词

| 术语 | 通俗解释 | 本项目中的作用 |
|---|---|---|
| `X` | 每个节点的一串数字描述 | GCN 接收的节点特征；不是类别标签 |
| text embedding | 把文本编码成数字向量 | 让模型能计算文本与图表示的相似度 |
| topology / 邻接 | 哪些节点连在一起 | 决定图模型从谁那里接收信息 |
| GCN | 会参考邻居信息的神经网络 | 读取 `X` 和边，输出节点表示 |
| teacher | 先用较完整的合法数据训练的示范模型 | 早期 ASM 用它规定希望模仿的响应 |
| student | 用小图训练的新模型 | 其真实图表现用来检验小图质量 |
| synthetic row / root | 小图中的一个训练节点 | 可以是聚合出来的数字和文本，不必是真实节点 |
| artifact | 导出的小图文件 | 像“封存的卡片版本”，可以重新加载和重训 |
| compact / condensation | 压缩后的小图 / 构造小图的过程 | 不自动意味着用了梯度优化 |
| frozen compact | 初始化后不再做 ASM 的小图 | 用来判断 ASM 是否真正带来收益 |
| seed | 随机数的起点 | 影响初始化、抽样、模型训练等 |
| ablation / 消融 | 只增删或改变一个候选组件的实验 | 判断收益究竟来自哪里 |
| gate | 进入下一阶段的实验门槛 | 不是神经网络结构；没过门槛就不把组件并入主线 |

特别注意：同一张小图训练 6 个 student，只增加了对训练随机性的了解，不等于独立做了 6 次凝聚。

## 4. 模型怎么在没有类别监督损失时学会分类？

训练时，每个节点有一个天然配对：这篇论文的图表示，应当与这篇论文自己的文本表示相似。

例如一个训练 batch 有三张卡片：

| 图节点表示 | 自己的文本是正例 | 同一 batch 中其他文本是负例 |
|---|---|---|
| 卡片 A 的图表示 | 文本 A | 文本 B、C |
| 卡片 B 的图表示 | 文本 B | 文本 A、C |
| 卡片 C 的图表示 | 文本 C | 文本 A、B |

模型练习的是“找回自己的搭档”。图找文本、文本找图两个方向都练，叫双向或对称 InfoNCE，也叫 CLIP 风格图文对比学习。

评测分类时，把候选类别写成提示文本，例如“a research paper about neural networks”。模型比较真实节点的图表示与这些类别提示的文本表示，选最相似的类别。

因此 GCN 不必直接读取字符串，文本仍然通过训练目标、文本投影和分类提示发挥作用。

这里说的“零样本分类”，主要指不使用训练节点类别标签构造通常的分类监督损失，并用类别文本提示预测；不等于这些类别从未作为图文训练内容出现过。

还要区分两层权限：准备程序会用标签划分类别阶段，dev 标签会用于选模；所以不能把整个流程宣称为完全不接触标签。

## 5. 怎样看实验数字？

- Accuracy：所有节点中，猜对了多少比例。大类别更容易主导它。
- Macro-F1：先分别评价每个类别，再平均，更关注小类别是否也能被识别。F1 同时惩罚漏判和误判。
- dev/checkpoint：开发时用来选参数、选训练时间点的分区。
- test/confirmation：候选固定后再报告的评估分区。旧 Cora 分区被反复用于开发后，不能继续当全新测试集。
- current：本阶段新到达类别上的表现。
- old：历史阶段上的表现；具体是平均还是合并计算，要看对应报告。
- cumulative：把所有已到达阶段的评估节点合在一起重新计算。
- future：对尚未到达阶段的诊断；早期协议允许预先看到全部类别提示，但不允许未来训练数据进入凝聚。

例如 40 提高到 45，是提高 5 个百分点，记为 `+5 pp`，不是相对提高 5%。

累计 Macro-F1 不能用 old 和 current 的算术平均还原。不同阶段之间的误分类会改变各类别的误报数量。

## 6. 全项目有三套设置，不能混着比数字

| 研究时期 | 下游与数据协议 | Cora 预算例子 | 主要用途 |
|---|---|---|---|
| 官方 TAGSAM 复核 | 官方 GCN+BERT；五类原 evaluator，另做七类复评 | 静态 size=50 | 核查官方实现和复现差距 |
| native ASM / Text-Anchored | 受控 GCN+BERT；源节点 ID 哈希 70/15/15；阶段训练诱导图 | 5%：25→67→94 | 定位静态和持续凝聚问题 |
| GraphCLIP 派生 / frozen_v1 | MiniLM 文本塔＋简化两层 GCN student；新的分区与整图推理协议 | 5%：32→87→121 | 验证确定性构造、持续算子和最终候选 |

后期 Citeseer 的预算是 50→110→143。预算变化来自数据池、划分和协议变化，不是同一运行偷偷增加容量。

因此，native 的约 77 分和 GraphCLIP 派生管线的约 54 分不能用来判断换模型后“掉了 23 分”。官方静态的 Accuracy 也不能与 native Macro-F1 直接横比。

# 第二部分：从“复现 TAGSAM”到“给 ASM 加文本锚”

## 第 1 步：起初只是想把官方 TAGSAM 跑通

**当时想回答什么？**

先复现静态 TAGSAM。若一张小图可以稳定训练出有效 student，才有基础研究“论文分批到达时，小图怎样更新”。

**具体怎么做？**

官方流程可以分成两件事。

第一件是制作初始卡片：选 synthetic 中心，收集邻域文本，用 GPT-2 相关性、条件信息和冗余等评分选句，拼出摘要；按照文本来源的抽取比例聚合节点 `X`，用冻结 BERT 编码摘要。这里的摘要偏向抽取拼接，不应自动理解为 LLM 自由生成。

第二件是改进卡片：teacher 在真实图上训练；新 student 在小图上练习；再让 student 回到真实 reference 节点上答题，对比它和 teacher 的图文关系，把误差传回 synthetic `X`。这就是 ASM。

官方 master 的小图主要使用自环；add-adj 分支另有 learned synthetic topology。两者是不同变体。

**结果与下一步。**

官方链路能运行，但结果不稳定，且与期望有明显差距。于是先检查“考试规则和程序是否可靠”，而不是立刻宣布方法无效。

证据：[官方静态复核](OFFICIAL_TAGSAM_STATIC_REAUDIT_2026-09-07.md)、[原始流程澄清](STATIC_TAGSAM_AND_CONTINUAL_PROTOCOL_CLARIFICATION_ZH_2026-09-08.md)。

## 第 2 步：先修复现的正确性，而不是开始发明新算法

**发现了什么？**

1. Cora 有七类，但官方 evaluator 写死只评前五类。
2. 把 `n_way` 改成 7 仍不够：旧五类 subgraph cache 可能被静默复用。相当于把试卷封面改成“七类”，里面仍是五类题。
3. master 与 add-adj 使用不同 topology，不能混成一个“官方结果”。
4. 尾批处理、设备和训练状态也需要修正或核查。

**具体怎么修？**

保留原版，单列三条链路：master、自带边的 add-adj、只做必要修复的 minimal repair。七类评测使用独立 cache；每份导出小图交给多个新 student 重训，不用某一次漂亮的分数代表整体。

七类 Test Accuracy 的代表结果是：

| 设置 | 不做外层更新，step 0 | step 500 |
|---|---:|---:|
| minimal repair，凝聚 seed 44 | 33.40 | 36.24 |
| minimal repair，凝聚 seed 45 | 33.81 | 38.74 |
| add-adj，独立五次 student 均值 | 38.58 | 40.23 |

同一七类接口下，完整真实图 teacher 为 61.12。这些是 Accuracy，不是 Macro-F1。

**应该怎样理解？**

不能说 ASM 一点用也没有：上述更新有小幅收益。但小图与 teacher 的差距仍然很大，不能假定“静态凝聚已经解决，剩下全是持续问题”。

修改尾批属于正确性修复；改拓扑、改初始化或损失则是方法变体。后面必须把这两类修改分开。

证据：[官方静态复核](OFFICIAL_TAGSAM_STATIC_REAUDIT_2026-09-07.md)。

## 第 3 步：建立 native v1，让问题变得可检查

**为什么不继续只用官方脚本？**

持续研究需要知道：当前能读取哪些数据？小图来自哪个阶段？哪个字段变了？artifact 被谁选中？重训的是不是全新 student？原始静态脚本不直接提供这套审计能力。

项目也讨论过 GraphCLIP，但马上迁移会额外引入文本空间、图塔、ego 子图、位置编码和可微训练适配。于是先选较可控的 GCN+BERT 路线。

**具体建立了什么？**

- Cora 按 `[0,1]→[2,3]→[4,5,6]` 到达。
- 源节点 ID 哈希划分 train/dev/confirmation；训练池排除留出节点。
- 各阶段训练图是不相交的诱导图，统一移除跨阶段边。
- 每阶段只允许读旧 synthetic memory 和当前 delta。
- 固定完整七类提示，分类时不提供任务 ID 帮模型缩小候选。
- 保存源数据、文本编码、代码和 artifact 的哈希与来源。
- 每个 artifact 导出后独立训练 student。

native 保留 GCN、冻结 BERT、图文 InfoNCE 和双层匹配思路，但把官方 GPT-2 文本选择换为 joint graph-text 聚类代表，并采用完整图传播、函数式 SGD 和自己的 row/column softmax BCE 匹配。

尤其注意：本地官方 minimal repair 的 `wBCELoss` 对 logits 做 sigmoid；native 的 `asm_loss` 对行、列分别 softmax 后做 BCE。二者不能称为公式完全相同的复现。

**下一步为什么测静态小图？**

新的后端还需要先证明“小图能教会新 student”，否则持续实验无从解释。

证据：[首版路线选择](../protocol/STARTING_ROUTE_SETTING_AND_MODEL_DECISION_ZH_2026-09-06.md)、[执行登记](../protocol/EXECUTION_PROTOCOL_2026-09-07.md)。

## 第 4 步：第一次关键分离——“小图有用”不等于“ASM 有用”

**具体怎么做？**

在同一个 native stage-0、5% 设置下，准备五种训练材料：完整原图、随机小集、代表点 coreset、未经 ASM 的 compact 初始化、ASM 后的小图。都让全新 student 去学习。

| 训练材料 | Test Macro-F1 | 通俗含义 |
|---|---:|---|
| Full-real | 83.24 | 看全部允许的训练材料 |
| Random-small | 69.73 | 随机留少量真实节点 |
| Coreset | 62.22 | 留代表性真实节点 |
| Frozen compact | 76.56 | 用图文联合初始化的小图，不再改 X |
| Offline ASM | 73.05 | 在 compact 基础上继续改 X |

**结果说明什么？**

Frozen compact 比随机小集好，说明整理卡片本身有效；但再经过 ASM，平均从 76.56 降到 73.05。这里更像“初稿有价值，自动修改没有稳定改善初稿”。

也有小预算、个别 seed 受益，例如 1% seed 44 曾比 Frozen 提高约 8 pp；另一个 seed 却失败。因此当时没有立即全面否决 ASM，而是继续寻找不稳定来源。

**研究问题改变了。**

从“增加多少 ASM 步数才能追上原图”，变为“ASM 改动了什么，为什么有时破坏已有训练信号”。

证据：[native 可行性报告](NATIVE_TAG_V1_FEASIBILITY_ATTRIBUTION_AND_PROGRESS_ZH_2026-09-07.md)、[逐项实验讲解](EXPERIMENT_WALKTHROUGH_ZH_2026-09-08.md)。

## 第 5 步：先把 ASM 的训练过程和选点看清楚

### inner 与 outer 到底是什么？

可以把 ASM 想成“改教材”的过程：

```text
拿当前小图 → 初始化一个临时 student
                 ↓
       用小图训练 student 若干步（inner）
                 ↓
       在合法真实 reference 上与 teacher 比较
                 ↓
       沿着训练过程反传，修改小图 X（一次 outer）
                 ↓
       再换一个临时 student，重复
```

inner 更新模型参数；outer 更新训练数据 `X`。正式评价时，还会另外训练独立 student，不能把临时 inner student 的表现当最终答案。

`outer=0` 指小图没有做 ASM；不代表评估 student 不训练。`student step=0` 则是学生还没训练，这是另一回事。

### 当时做了哪些稳定化检查？

- 固定或限制 inner 学习率，减少可学习步长失控风险。
- 单独减小 outer 学习率，检查是否只是更新过猛。
- 保留所有尾批，检查梯度有限、非零且确实能到达 X。
- 记录 X 范数、旧行漂移和真实样本暴露次数。
- 把 outer 0 纳入候选，保存最终点与选中点。
- student 检查由每 128 步加密到每 32 步，outer 后来每 20 步保存。
- 相同 source 的对照直接复用同一 teacher 实例，而不只是用相同 seed 重训一个“应该相同”的 teacher。

加密 checkpoint 曾让同一份 25 节点小图从约 65.80 提高到 77.84；这部分属于更好地捕捉训练峰值，不是凝聚算法突然变强。

减小 outer 学习率有时让 dev 好一点，却没有跨 seed 的确认收益。因此，“只要学习率再小一点”不是完整答案。

这些工作让后续讨论有了基础：我们知道 X 确实在更新，也能看见它是何时变好或变坏的。

证据：[归因执行补充](../protocol/ATTRIBUTION_ADDENDUM_2026-09-07.md)。

## 第 6 步：把静态 ASM 变成几种持续更新方法

**新的困难。**

静态 teacher 能看到完整历史；持续阶段只剩旧小图和当前原图。为了知道历史信息在何处丢失，先实现清楚的基线。

| 方法 | 实际做法 | 卡片比喻 |
|---|---|---|
| Append | 新 delta 单独凝聚，旧 memory 保留，最后拼接 | 旧卡片不改，只加新卡片 |
| Union | 旧 synthetic 与新 raw 合为 source，重新初始化和凝聚整个 memory | 把旧卡片与新全文放一起重编教材 |
| Append-joint | 旧块＋新 compact 初始化，联合 teacher/inner/reference，更新全部 X | 卡片先拼好，再一起修改数字内容 |
| Protected-joint | 与 Append-joint 相同，但旧 X 精确冻结 | 参考旧新整体，只允许改新卡片 |
| Full-history | 允许读取全部历史 raw | 可以翻回所有旧论文的宽松参照 |

这个时期的 joint 指联合图文对比与响应匹配，不意味着新增跨阶段图边。后期 frozen_v1 会重连语义边，是另一个协议。

### 先做两阶段，发现“再整理一次”可能丢信息

5% 的一组固定旧小图诊断中，Full-history 为 76.45，旧小图＋当前 raw 为 64.28；Union 再凝聚后为 52.13，而 Append 为 73.47。这些是 checkpoint 诊断，且旧小图＋raw 超预算，不能当同预算排行榜。

一个可见变化是：Union 初始化只保留旧 25 条文本代表中的 14 条，Append 保留全部 25 条。但 Union 同时改变了 X、文本选择和 topology，不能把差距全部算在“少了 11 条文本”头上。

### 还检查了旧节点在 reference 中是否被淹没

旧 25 行小图代表 510 个训练节点，却只占合法 source 的 25/874 行。均匀抽 128 个 reference 时，实际仅约 4 行来自旧阶段。

于是尝试按 mass 加权损失、增加旧阶段 reference 配额。它们没有给出足够收益：问题确实存在，但尚未证明是主要掉点原因。给一张旧卡片更大的权重，也不能恢复它已经丢失的所有原文细节。

### 三阶段后，简单 Append 仍是强基线

后续汇总的累计 test Macro-F1 约为：Full-history 49.37、Append 37.56、Protected-joint 37.44、Append-joint 36.53、Union 35.53。

应读成“宽松 raw 参照约 49，各 compact 约 35–38，联合更新没有稳定胜过追加”，而不是抓住 0.1 分宣布胜负。不同历史报告还存在共享 teacher、固定标签集合等版本补正，应在同一表内比较。

至此，第一版持续机制 Protected-joint 尚未成立为有效新方法。下一步要拆开旧材料、新材料和更新过程。

证据：[native 可行性报告](NATIVE_TAG_V1_FEASIBILITY_ATTRIBUTION_AND_PROGRESS_ZH_2026-09-07.md)、[归因补充](../protocol/ATTRIBUTION_ADDENDUM_2026-09-07.md)、[逐项实验讲解](EXPERIMENT_WALKTHROUGH_ZH_2026-09-08.md)。

## 第 7 步：先拆材料——是旧 memory 不好，还是新块不好？

**具体怎么做？**

固定 stage-1 的 67 行旧 memory。stage 2 新到 532 个训练节点，总预算 94 行，所以新块只能占 27 行。

| 输入组合 | 总行数 | 累计 checkpoint F1 |
|---|---:|---:|
| Full-history raw | 1891 | 51.16 |
| 旧 memory 单独使用 | 67 | 38.70 |
| 旧 memory＋全部新 raw | 599 | 47.39 |
| 旧 memory＋随机 27 个新 raw | 94 | 40.08 |
| 旧 memory＋27 行新 compact | 94 | 42.98 |

**怎样理解这张表？**

- 同样只给新信息 27 行，compact 比随机 raw 好：整理卡片有用。
- 但 compact 不及保留全部 532 个新节点：27 张卡片仍有信息容量损失。
- 全量历史更好：旧卡片也没有保存全部历史信息。

再把旧 memory 换成较差的 Union 产物，保持同一个新 compact，累计从 42.98 降为 33.18。这说明旧阶段怎么走过来，会影响后面；误差具有路径依赖。

**进入下一步的理由。**

旧块和新块都存在缺口，但还不知道是代表选择、X、文本、topology 还是优化造成的。因此要继续做更细的字段对照。

这些差值不是可以简单相加的“损失账单”。有些对照同时变化多个字段，有些使用更多行，只是用于定位问题。

证据：[stage-2 组成归因](STAGE2_SOURCE_COMPOSITION_ATTRIBUTION_2026-09-07.md)。

## 第 8 步：再拆更新——只冻结旧 X，或者只改新 X，能解决吗？

**实验 A：其他东西都一样，只切换旧 X 是否可更新。**

| 凝聚 seed | 不做 ASM | 新旧 X 全更新 | 只更新新 X |
|---|---:|---:|---:|
| 44 | 44.75 | 45.05 | 43.59 |
| 45 | 34.59 | 34.59 | 36.00 |

seed 44 看起来应该改旧 X，seed 45 看起来应该冻结。最后迭代的旧 X 相对漂移达到约 1.21–1.30，说明修改并不小，却没有稳定的好方向。

**实验 B：固定旧 memory，比较新块是否需要继续 ASM。**

两个凝聚 seed 的累计 dev 均值：随机新 raw 为 36.21，compact 初始化为 39.63，新块单独 ASM 为 39.17，Joint 为 39.64，Protected 为 39.72。

改善主要来自“构造 compact”，而不是“继续 ASM”。联合训练和旧 X 冻结都只有非常小且不稳定的均值差异。

**下一步。**

不能把“冻结旧 X”当最终答案。先检查 X 的初始化方式和完整更新轨迹，不急着添加跨阶段边或更复杂的关系模块。

证据：[细粒度归因](FINE_GRAINED_CONTINUAL_TAG_ATTRIBUTION_2026-09-07.md)。

## 第 9 步：检查“均值 X”与“ASM 轨迹”

**疑问一：把一群论文 X 取平均，会不会天然与代表文本不配？**

固定同一批代表 ID、文本、权重和边，只把新块 X 从簇均值换成代表论文的真实 X。

- seed 44：44.75→44.18，下降 0.57 pp。
- seed 45：34.59→36.49，提高 1.89 pp。

方向仍相反，不能把 centroid X 定为稳定主因。

**疑问二：只看最终选中的 outer，会不会掩盖发生了什么？**

固定保存 outer 0、20、40、60、80、100，每份小图都独立重训 student，并分别查看每个历史阶段。

- seed 44：stage 1 从 69.99 降至 55.03，stage 0 却没有同步下降。
- seed 45：stage 1 从 42.96 升至 59.88，同时 stage 0 从 76.05 降至 68.80。

通俗地说，自动改教材有时修好了第二章，却改坏第一章；另一次则刚好相反。一个总分看不出章节间的冲突。

此时问题进一步收敛为：X 更新后的图响应，是否还和固定文本保持同一个意思？

证据：[字段级 X 与 outer 轨迹诊断](DIAGNOSTIC_X_OUTER_TRAJECTORY_2026-09-08.md)。

## 第 10 步：直接检验“图与它自己的文本”是否重要

### 实验一：只把搭档换错，不改变材料总量

固定 X、边、权重和 ID，只在同阶段内部打乱文本配对。

例如原来是“神经网络图特征—神经网络文本”，打乱后变成“神经网络图特征—概率方法文本”。小图里仍然有原来那一批文本，只是不再贴在正确的卡片上。

2 个凝聚 seed × 3 个置换 seed，共 6 次，当前阶段 test 全部下降，平均约 11.20 pp。

这直接支持：有用的不只是文本总集合，而是每个图根与具体文本的一一对应。

### 实验二：不看类别标签，检查 ASM 是否正在破坏这种对应

用同一冻结 teacher 读取每个 outer 的小图，测它的图表示是否容易找回自己的文本。用 symmetric InfoNCE 表示错误，越低越好。

| seed | outer 0 | outer 100 |
|---|---:|---:|
| 44 | 1.54 | 2.27 |
| 45 | 1.06 | 2.07 |

两个 seed 都恶化；这个过程文本、边和 ID 没变，只有 X 变了。

**因此形成候选机制：** ASM 在真实 reference 上追求模仿 teacher，却可能让 synthetic X 偏离原来配对的文本。置换实验说明配对重要，对齐轨迹说明 X 更新确实伴随配对恶化；它们一起支持针对性修补，但还不是对全部性能损失的穷尽证明。

证据：[轨迹、置换与对齐诊断](DIAGNOSTIC_X_OUTER_TRAJECTORY_2026-09-08.md)。

## 第 11 步：这时才提出 Text-Anchored ASM

**它要补哪个洞？**

原目标只问：“学生在参考材料上像不像老师？”

新加的目标问：“这张 synthetic 卡片的数字内容，还找得回它自己的文本吗？”

用公式简写：

\[
L=L_{ASM}+\lambda L_{text\text{-}anchor}.
\]

第一项是原本的响应匹配；第二项用冻结 teacher 在 synthetic 图上做 graph-text symmetric InfoNCE。teacher 和文本冻结，但对输入 X 的梯度保留，所以约束可以直接推动 X 回到与文本对应的方向。

第一版候选为 `lambda=0.01`、`scope=all`，即对全体 synthetic rows 加约束。代码保留 `lambda=0` 作为原路径，分别记录两个 loss。

### 为什么要做两种比较？

同 outer=60 对照：新方法和原方法都运行 60 次，累计 test 为 39.72 对 35.38，提高 4.34 pp。这说明在相同优化时长下，锚定项确实能缓解伤害。

各自 dev-best 对照：原 ASM 最好可能停在 20 次，而不是 60 次。让它也使用自己开发集选出的好时刻，差距缩小为 39.72 对 38.26，即约 +1.47 pp。

所以不能只选较大的 +4.34 pp 宣布整体算法明显更好。它主要是机制证据，公平选模后的效用差距更小。

### 为什么还要做严格递归？

先前 stage-2-only 是从同一份固定旧 memory 出发。真正的方法必须从 stage 1 就参与更新，再把自己产生的小图传到 stage 2。

严格递归中，stage 1 的 ASM 与 Text-Anchored 轨迹都选回 outer=0；stage 2 平均有所改善，但凝聚 seed 44 为负、45 为正，不稳定。

**这一阶段的结论。**

Text-Anchored 是由证据支持的局部修补，不是最终解决方案。下一步不能只是再加几个 loss，必须回头问：究竟是整个优化路径不工作，还是保持目标选错了？

证据：[Text-Anchored 技术报告](TEXT_ANCHORED_ASM_TECHNICAL_REPORT_ZH_2026-09-08.md)。

# 第三部分：为什么后来不再优化 ASM，而转向确定性构造？

## 第 12 步：重新核对论文和静态优化，避免错把静态问题当持续问题

**为什么回头看？**

严格递归的 stage 1 一直选 outer=0。它可能不是“旧知识保持不够”，而是更基本的“开始优化就不好”。如果静态阶段也如此，再加持续保持约束可能补错地方。

### P1：论文数字与本地复核分开看

项目校准报告摘录的论文 Cora size50 五类 Accuracy 为 73.8；本地 master 约 38.2–42.8，add-adj 约 51.2–52.9，存在尚未解释完的较大差距。

还核对了官方 `distill.py` 确实调用文本选择，不能再把问题简单解释成“整个 text selection 没有执行”。缓存内容和指纹仍是需要审计的另一层问题。

这支持继续诊断本地复现，但不能据此断言论文错误。任务采样、超参和实现差异没有被完全排除。

### P2：直接看 loss 和梯度，而不是只看分数

5 个凝聚 seed（44–48）× 3 个 outer 学习率（0.01、0.003、0.001），共 15 个 run，记录 ASM loss、X 梯度、outer 轨迹与独立 student 表现。

观测到：

- native ASM 100 步 loss 仅下降约 0.2%–1.2%；
- X 梯度范数约 0.0002–0.0012；
- 官方 master 的 500 步 syn_loss 也仅下降约 4.7%；
- frozen 初始化本身跨 seed 从约 49.9 到 80.1，差异远大于稳定的优化收益。

一个坏初始化 seed 48 被更新后可从约 49.9 提高至 74.8；但好的初始化常选回 outer=0。这说明不能说更新“绝对无用”，而是没有稳定可靠的改进规律。

**通俗解释。**

改教材的程序每次只收到很弱的修改信号，但教材初稿有的很好、有的很差。于是修改有时碰巧修好坏初稿，有时却破坏好初稿。

loss 几乎不降与梯度很小支持“当前配置的优化驱动力弱”。至于是否主要由 inner unroll 衰减造成，还不能仅凭这些数值证明唯一根因。

**当时的取舍。**

把注意力从“继续调 ASM”转向“让初始化稳定”。这是一项针对已测实现和配置的研究决策，不是证明双层优化在所有 TAG 上都不可能成功。

证据：[论文校准](TAGSAM_PAPER_CALIBRATION_ZH_2026-09-08.md)、[P2/P3 诊断](STATIC_DIAG_AND_BUDGET_ALLOC_RESULTS_ZH_2026-09-08.md)。

## 第 13 步：P3——是否只需要给新信息更多预算？

**具体怎么做？**

仍在 native stage 2，总预算 94 行不变，扫描旧/新分配：67/27、55/39、47/47、32/62，比较 seed 44、45。

**结果。**

- seed 44 的旧 memory 较好，多保旧行更合适。
- seed 45 的旧 memory 较弱，把空间让给新信息反而更合适。

因此，“给新块越多越好”和“永远保护旧块”都不成立。

**通俗解释。**

同样只有 94 张卡片的位置，如果旧卡片质量很好，扔掉它们很亏；如果旧卡片已经很差，保留更多也不一定有价值。

这一步先提出质量相关的预算分配方向。但后来没有真的训练一个“质量自适应分配器”；最终的 c=15 是简单容量规则，不能把它说成已经学会了 memory 质量。

证据：[P3 预算诊断](STATIC_DIAG_AND_BUDGET_ALLOC_RESULTS_ZH_2026-09-08.md)。

## 第 14 步：P5——如果强行保持 teacher 的回答，会不会有效？

**Text-anchor 与 response-retention 有什么区别？**

- Text-anchor 要求卡片的图表示找回自己的文本，像“标题和内容别配错”。
- Response-retention 要求更新前后 teacher 对类别提示的分数分布接近，像“改完后老师的答题倾向别变”。

后者会保存 teacher 在 synthetic rows 上对 class prompts 的响应分布，再用 KL 损失保持。KL 可以理解成“两份概率答案有多不一样”。不需要把节点真实类别作为训练目标。

**具体怎么做？**

5 个凝聚 seed × 4 个 retention 权重（0、0.05、0.1、0.3），共 20 个 stage-1 run；固定 text-anchor 权重 0.01。旧行 target 来自旧阶段 teacher，新行 target 来自当前 delta teacher。

**发生了什么？**

retention KL 从约 0.06–0.32 降到 0.001–0.005，下降 92%–99%。也就是说，这个目标确实容易优化，梯度路径没有完全失效。

但没有一个凝聚 seed 满足 gate 的稳定改善要求。多数仍选 outer=0；seed 45 的零权重对照曾选 outer=80，但增益仅约 0.09 pp，不能据此视为稳定通过。

**这是非常关键的转折。**

此前可以说 ASM 是“目标想得不错，但优化不动”；现在出现一个目标被优化得很好，而新 student 仍然没有学得更好的例子。

老师面对改后的卡片仍能给出原来的回答，不代表没学过的新学生能靠卡片学会知识。老师已经会了很多东西，它对材料的使用方式与新学生从头学习不同。

所以结论收敛为：

> 保持某个冻结模型的前向响应，不足以保证小图的可重训性。

项目据此停止把这些响应约束作为主线，保留为负结果和消融。不能进一步写成“所有响应蒸馏方法都不可能有效”。

证据：[Stage-1 retention gate](STAGE1_RETENTION_GATE_RESULTS_ZH_2026-09-08.md)。

## 第 15 步：第一版构造式方法——不再反复改卡片，先把卡片整理好

**新的想法。**

既然 frozen 初始化最重要，先让它不再依赖“这次随机抽得好不好”。

**具体怎么做？**

1. 用联合图文特征把节点放进一个相似度空间。
2. 第一个代表点按固定规则选，后续每次选离已有代表最远的点，叫 max-min 或 farthest-point 播种。
3. 反复把节点分给最近中心、更新中心，叫 Lloyd 迭代。
4. 每簇选择靠近中心的真实代表节点，使用它的真实 X 与文本。
5. 用文本相似度构造边，替换带训练随机性的 link predictor。

想象要选城市地图上的几个服务站：不要随机抽位置，而是每次在当前最没被覆盖的地方加一个站。之后再把站点位置向服务人群的中心调整。

这不是完全“没有计算”。它做了迭代聚类，但不训练 teacher，不通过双层神经网络反传去修改 X。

**结果。**

旧 frozen 跨凝聚 seed 均值约 67.77、标准差 11.74、最差 49.92。确定性 real-X、边预算参数 2.0 的两批独立 student 均值为 78.14 和 76.31。

小图构造不再由随机 seed 抽签，但 student 训练仍有随机波动。不能把“无凝聚随机性”说成“每次最终分数都相同”。

边太多也不好：参数 3.0 时降到约 42.78。邻居消息可能把不该混在一起的语义混合。

**为什么这还不是最终版？**

这一版保留真实 medoid X 和单条代表文本。后续用户约束要求 synthetic X、文本融合，以及 GraphCLIP 方向的下游，因此继续迁移，而不是把 77 分直接当最终方法成绩。

证据：[确定性构造式 gate](CONSTRUCTIVE_GATE_RESULTS_ZH_2026-09-08.md)。

## 第 16 步：迁移 GraphCLIP 派生管线，改成均值 X＋融合文本

**约束发生了什么变化？**

目标转向 GraphCLIP 相关下游，允许简化；小图不以复制真实节点作为主要表示；文本要融合而不是仅挑一条。

**具体改了三件事。**

第一，从 GraphCLIP checkpoint 提取 MiniLM 文本塔，统一重新编码。BERT 的 768 维 embedding 不能直接冒充 MiniLM 的 384 维 embedding。

第二，student 用两层 GCN 图塔替代官方 GPS 图塔，保留 CLIP 风格图文训练。因此它是简化 GraphCLIP 风格接口，不是官方完整 GPS 模型的原样训练。

第三，每簇 X 取均值；选最靠近簇中心的 g 条原文，截断拼接，再用冻结 MiniLM 编码这个新文本。

例如一个簇有 20 篇关于神经网络训练的论文：

- X 是这 20 行原始数字特征的均值；
- 文本选最多 5 篇靠近簇中心的论文，各取一个短片段拼起来；
- embedding 是对拼接结果重新编码，不是简单平均 5 个 embedding。

这样 X 与融合文本有共同的来源簇，但不等于已经数学保证两者语义完全一致。

**结果。**

扫描 g=1、3、5、7、9。g=1 相当于单条文本，开发分数约 49；g=5/9 可达到约 53–54。长训练下 g=5 为 54.52±1.23，高于三组随机真实节点抽样的约 50.38、52.09、51.67。

**取舍。**

这支持“简单文本融合有训练效用”。最终选 g=5，边预算参数在这个新文本空间改为 1.0。参数变化属于新管线重新选择，不可套用早期 native 的 2.0。

注意，均值生成的 X 不保证永远不等于真实 X：簇只有一个成员时，均值就是那一行。这里的“全合成”是构造规则描述，不是匿名化或零泄漏保证。

证据：[GraphCLIP 构造式 gate](GRAPHCLIP_CONSTRUCTIVE_GATE_RESULTS_ZH_2026-09-08.md)。

## 第 17 步：S2——把更复杂的组件加回来，看看简单方案是否只是暂时领先

**为什么要做？**

现在方法看起来很朴素：聚类、均值、拼文本、按文本连边。为了知道是否还应该回收 TAGSAM 的组件，设计了三个方向的对照。

| 候选改动 | 实际怎么做 | 当时的期望 | 相对基线结果 |
|---|---|---|---:|
| det-CMI 选文本 | GPT-2 条件 NLL 等纯前向评分选候选片段 | 比只选近邻更有信息量 | 54.17→46.99 |
| 真实边粗化 | 将真实边投影成簇间边，按规模归一化后筛边 | 保留原图结构 | 54.17→43.74 |
| 一阶 X 精炼 | 固定随机图算子，优化图文 InfoNCE，并用 L2 拉住原均值 | 不穿长 inner loop，也能改善 X | 54.17→41.17 |

还有混合 topology 47.96、多个组件叠加 40.59。当前已测配置没有优于简单基线。

### 用卡片比喻理解失败机制

- 信息量高不一定切题：一句出乎意料的话可能有新信息，也可能离题。掺进拼接文本后，会影响整段 embedding。
- 真实边聚合不一定适合小图：很多真实引用汇成少数簇间连接，可能形成连接高度集中的 hub，改变 GCN 的消息传播。
- 固定代理算子答得好，不代表新 student 学得好：精炼可能把 X 调成“特别适合这个固定算子”，却偏离可迁移的数据统计。

这些是与观测相符的机制解释，不是每个原因都经过独立消融严格证明。特别是 S2 主要是 Cora 单预算点，不能宣称所有 CMI 或图粗化技术都被否定。

**取舍。**

不把已测的复杂组件并入 v1，保持均值 X、几何近邻文本融合、文本相似边。简单性是在比较之后留下来的，不是事先断定“越简单一定越好”。

证据：[S2 消融报告](GATE_S2_ABLATION_RESULTS_ZH_2026-09-08.md)。

## 第 18 步：重新测试持续算子——旧卡片究竟该不该重新整理？

现在已不再用 ASM 优化主线，比较的是确定性构造的三种更新方式：

- append_fixed：旧行不改，只构造新块。
- recluster：旧 memory 按代表人数 mass 加权，与当前 raw 一起重新聚类；可能合并旧簇、混合旧新信息并再次融合文本。
- full_history：重读所有原始历史，在联合池里一次重新构造同预算小图。

后期这里的 full_history 是“重读历史后再凝聚”，不是 raw 直接训练；早期 native 表中的 Full-history 常是 raw 训练参照。同名在不同 runner 下要看输入。

### recluster 不是随便拼接，而是做了认真设计

旧卡片可能代表 20 篇论文，新 raw 行只代表 1 篇，所以旧卡片以 mass=20 参与；合并时继承总 mass，文本按纯旧、纯新和混合情况处理，还用 depth 记录融合深度，减少旧文本被反复截断稀释。

但设计得复杂、合理，不等于最终效果就好。

### 先发现训练步数是一个混淆因素

stage 0 只有 32 行，统一训练 2048 步时分数约 28.7；很短训练曾约 70。说明小图可能被反复训练过头。报告采用 `steps=min(2048,16×roots)` 后重跑。

修正后的 Cora stage-2 dev：

| 方法 | 累计 | 历史 | 当前 |
|---|---:|---:|---:|
| append_fixed | 53.56 | 75.44 | 48.05 |
| recluster | 44.74 | 66.25 | 40.43 |
| full_history 重凝聚 | 51.63 | 62.68 | 65.95 |

**怎么理解？**

追加更擅长保住历史，联合全历史重凝聚更擅长当前阶段；recluster 在这组 Cora 实验中两头都没有做好。持续算子因此采用“保留旧行内容，只追加新块”。

append 的 53.56 比 full_history 的 51.63 高约 1.9 pp，但小样本下不宜仅凭均值宣布显著胜出。更稳妥是“累计不劣，历史保持更好”。

代码边界：缩放训练步数在后期 Gate2/Gate3/corrections 等 runner 中落实；当前本地基础 Gate1 runner 仍直接传统一 `--student-steps`，不能用其默认命令宣称自动复现报告中的 scaled 结果。

证据：[Gate1 持续结果](GATE1_CONTINUAL_RESULTS_ZH_2026-09-08.md)。

## 第 19 步：最后的预算选择——旧卡片可以删，但不重新改写

**为什么还要改预算？**

旧 memory 有 87 行，总预算 121，默认只剩 34 行给 3 个新类。append 历史很好、当前较弱，是否给新块一点空间就能改善？

**具体怎么做？**

按 mass 删除一部分旧行，保留行的 X 和文本不变，分别构造 34、44、54、64 行新块。

| 旧保留/新块 | 累计 dev | 历史 | 当前 |
|---|---:|---:|---:|
| 87/34 | 53.56 | 75.44 | 48.05 |
| 77/44 | 53.13 | 67.76 | 54.06 |
| 67/54 | 48.92 | 74.15 | 37.67 |
| 57/64 | 47.28 | 68.72 | 40.45 |

给新块 10 行，当前提高约 6 pp，但历史下降约 7.7 pp，累计下降约 0.4 pp；继续扩新块则反而变差。容量分配不是越极端越好。

因此冻结一个温和规则：

```text
新块行数 = max(预算余量, 15 × 本阶段新类数量)
旧块可保留行数 = 总预算 - 新块行数
若旧块放不下，按 mass 从小到大删行
```

关键区别：扫描点是 keep77/new44；c=15 的实际 Cora 落点是 keep76/new45，不是同一个精确配额。

另一个关键区别：“每新类 15 行”只是按新类数量计算新块总额度。簇的构造没有按类别分别分配，因此不保证每个新类恰好或至少获得 15 个纯类簇。

### 为什么不做一个自动调预算的学习器？

现有收益窗口窄且非单调；在每个阶段反复训练 student、看 dev 后决定 memory 预算，会增加开销和模型选择复杂度。这里选择常数 c 是工程与证据上的取舍，不是说离散预算在理论上绝对无法学习。

### 补上 raw 直接训练参照

2437 个 raw 节点在更长、上限 8192 步的训练安排下，累计 dev 约 45.29，仍低于表中的 compact 候选。

这提示压缩可能还起到减少冗余和假负例的作用：原图中很多同类论文在 InfoNCE 中被当作互相排斥的负例，而聚类融合降低了这种重复。

但“凝聚就是去噪”仍是机制假设。raw 与 compact 的 topology、采样、每行暴露量均不同，8192 步也不证明 raw 在一切超参下充分收敛。“raw_upper”只是宽松权限参照的名字，不是数学上界。

证据：[预算扫描与 raw 参照](BUDGET_SWEEP_AND_RAW_UPPER_ZH_2026-09-08.md)。

## 第 20 步：换到 Citeseer，检验是不是只对 Cora 有用

**具体怎么做？**

Citeseer 有 6 类，按 `[agents, ML]→[IR, DB]→[HCI, AI]` 三阶段到达，预算 50→110→143。核查类别 ID 与 prompt 的映射，再用相同构造和 student 协议重跑。

stage-2 dev：

| 方法 | 累计 | 历史 | 当前 |
|---|---:|---:|---:|
| append_fixed | 61.26 | 78.88 | 50.52 |
| recluster | 58.80 | 73.56 | 65.28 |
| full_history 重凝聚 | 49.64 | 64.17 | 47.36 |
| raw 直接训练 | 55.96 | 70.80 | 58.60 |

**原来的说法必须变得更准确。**

append 累计和历史更好，但 recluster 当前阶段高出约 14.8 pp。审计看到 recluster 产生了 54 个旧新混合簇，相当于新类借用了旧卡片的位置。

因此，recluster 不只是“把旧信息改坏”，它也在进行隐式容量再分配：牺牲部分历史保持，换来更高新类塑性。不能说“再聚类所有时候、所有指标都差”。

c=15 在这里不触发：两个新类的总额度下限是 30，而默认余量已经是 33。额外预算扫描也没有找到稳定优于默认累计分数的温和调整。

**最终定位。**

方法选择一个偏向历史保持、累计效用不劣且构造随机性小的运行点，不声称同时最大化所有指标。

证据：[Gate2 Citeseer 结果](GATE2_CITESEER_RESULTS_ZH_2026-09-08.md)、[修正与预算迁移](OFFICIAL_GRAPHCLIP_COMPARISON_AND_CORRECTIONS_ZH_2026-09-09.md)。

## 第 21 步：回应两个问题——是否比官方差很多？是否只是联合构造器太弱？

### 问题一：简化模型分数只有 54–61，是不是方法太弱？

直接加载官方预训练 GraphCLIP：12 层、1024 维 GPS 图塔与同源文本塔，按官方 ego 子图和随机游走位置编码协议评测。

官方 dev Macro-F1 为 Cora 57.47、Citeseer 62.90；项目选取的派生 student 参照为 54.52、61.26。

这给出同类任务的绝对水平参照，但不是严格同条件模型消融：官方是预训练模型直接推理，项目是小图上从头训练；官方用 ego 子图，项目用整图传播。Cora 的 54.52 还是前面的静态构造参照，不应冒充最终持续 c15 的 test 数字。

因此可以说“差距量级不大”，不能断言 54–61 就是这个文本塔的任务天花板。

### 问题二：append 胜 full_history，是不是只因为联合聚类器不够强？

补一个更对齐的对照：允许一次读取全历史，但不混成一个池；按原阶段配额分别构造，再拼起来。

如果构造器是确定的，则：

```text
在线：第一阶段构造块0并存下 → 后面构造块1、块2 → 拼接
离线：同时看到历史 → 对同样阶段分别构造块0、块1、块2 → 拼接
```

在相同输入、顺序、配额和实现下，二者没有理由产生不同的块。这说明“不能重读历史”不一定额外损伤这个分块构造方案。

但是参照必须限定为“相同分阶段构造器”。不代表它与最优离线凝聚器等价，也不证明时间分层永远胜过类别平衡的联合方法。若含删行，离线参照也必须重放同样删行规则。

本地 corrections 审计用 `allclose(atol=1e-5)` 比较 x/text_emb/mass/stage，用精确相等比较 texts；没有检查 depth。因此应称“已检查关键字段在容差内一致”，不能把该代码描述为所有字段逐位相等的证明。

证据：[官方对比与等价性修正](OFFICIAL_GRAPHCLIP_COMPARISON_AND_CORRECTIONS_ZH_2026-09-09.md)、[corrections 代码](../../code/frozen_v1_2026_09_09/run_corrections.py)。

## 第 22 步：冻结方法，再读一次确认分区

**冻结了什么？**

- 确定性联合聚类；
- 均值 X；
- 最接近簇中心的 5 条文本截断拼接并重编码；
- 文本相似度选边，参数 1.0；
- append＋c=15，必要时只删旧行；
- 5% 根节点预算；
- 两层 GCN＋文本投影 student，6 个训练 seed；
- 常规小图训练步数 `min(2048,16×roots)`。

Gate3 用 `node_id % 10 == 2` 作为确认计分分区，报告称是在冻结候选后首次作为该确认分区读取。其节点特征和文本之前已经参与 transductive 构造，不是完全未见样本。

报告的 test cumulative Macro-F1：

| 方法 | Cora | Citeseer |
|---|---:|---:|
| 冻结方法 | 58.07 | 56.99 |
| 默认 append（Cora 不调 c） | 55.23 | 与方法相同 |
| recluster | 44.26 | 54.90 |
| full_history 重凝聚 | 53.58 | 48.40 |
| raw 直接训练 | 43.95 | 51.82 |

Cora 的 c15 相对默认 append：累计约 +2.85 pp、当前 +7.61 pp、历史 −2.05 pp；是有代价的容量交换，不是免费提升。

**结论。**

已选方法在这份确认表的累计指标上两数据集均居首，支持冻结当前版本。它不代表所有消融的机制解释都被 test 重新证明，也不代表所有指标都最优。

权限上还要谨慎：代码用 y 定义阶段，test 节点可处于非 dev 的构造池；因此“test 标签从未被任何程序读取”不是字面成立的代码级保证。更准确的目标是确认计分标签未用于此前方法选择。该历史声明仍需跨运行记录核查；已有旧报告也明确说 Cora 曾被用于开发，不能仅凭一次新划分消除历史暴露。

本版本 test 已消费，后续改方法应使用新验证安排，最好增加真正未参与开发的数据集。代码的拒绝覆盖与标记不是全局访问控制：换输出目录仍可能再次执行，所以还需要流程纪律。

证据：[冻结声明](../../code/frozen_v1_2026_09_09/FREEZE_DECLARATION.md)、[Gate3 确认表](GATE3_TEST_CONFIRMATION_ZH_2026-09-09.md)。

# 第四部分：把最终方法在脑中运行一次

前面解释了为什么选择这些组件。现在不再讲历史，直接看 frozen_v1 到底怎样处理一批数据。

## 1. 输入、输出分别是什么？

本阶段输入是当前允许读取的 `X`、raw texts，以及旧 synthetic memory。核心构造不依赖旧原图，也不依赖跨阶段保存的 teacher 或 optimizer。

输出 memory 含这些字段：

| 字段 | 内容 | 可以怎么理解 |
|---|---|---|
| `x` | 每簇的均值特征 | 卡片的数字内容 |
| `texts` | 截断后拼接的文本 | 卡片的可读文字 |
| `text_emb` | 对这段文字重新编码的向量 | 同一文字的机器可读版本 |
| `mass` | 该行最初代表多少个真实节点 | 这张卡片背后有多少篇论文 |
| `stage` | 该行的来源阶段 | 哪一批产生的卡片 |
| `depth` | 文本再融合深度 | 主要供 recluster 消融审计，append 新块通常为 0 |

topology 不作为这份基本 memory 的必需字段保存，而是在 `memory_to_trainable` 中从当前全体文本 embedding 重建。

`mass` 不是“这张卡片的预测准确率”。它只是代表数量。按 mass 保留大簇可能偏向多数语义，不能当作无损的质量筛选。

## 2. 先把 raw text 变成可以算距离的向量

`FrozenMiniLM.encode` 做四件事：

1. tokenizer 将句子切成 token；
2. 冻结模型给每个 token 一个 hidden vector；
3. 根据 attention mask 取有效 token 的均值，排除 padding；
4. L2 归一化，获得文本 embedding。

相当于把每篇论文放在一张语义地图上，意思接近的文本尽量靠近。

MiniLM 全程 `eval` 和 `no_grad`，不随阶段训练。后面 student 的文本投影仍会训练，它是另一个模块。

## 3. 拼接图特征与文本特征，然后聚类

代码使用：

```python
joint = torch.cat((F.normalize(x.float(), dim=1), text_emb), dim=1)
assign = weighted_cluster(joint, torch.ones(len(x)), k)
```

通俗地说：不仅看论文的图特征，也看文字意思，把两种信息拼成一个位置，再将相近论文归组。

在 frozen 管线中，典型 X 和文本各 384 维，拼后是 768 维。这里的拼接不是将 raw 字符串放进 GCN。

注意真实代码是 `dim=1`，两块分别逐行 L2 归一化。原回顾示例中 `F.normalize(x.float(), 1)` 的写法会让 1 变成 `p=1`，应避免照抄。

### 用四个数字理解 max-min＋Lloyd

下面只是教学用的一维坐标，不是实际论文 embedding：

```text
A=0.0，B=0.1，C=10.0，D=10.1，需要分成两簇
```

所有 mass 都是 1。首点取固定输入顺序中的 A；第二点取离 A 最远的 D。

接着按最近中心分配，A、B 归第一组，C、D 归第二组。中心更新为 0.05 和 10.05；再次分配没有改变，就可以结束。

真实算法在高维中做同样的事，最多 25 轮。它还强制最初选出的种子保留在自己的簇，减少平局导致的空簇问题。

若是被保留的 recluster 消融，旧点 mass 可能为 20、新点为 1；更新中心时旧点的贡献按 20 份计算。最终 append 新块只对 raw delta 聚类，输入 mass 都是 1。

“确定性”首先是指不随机抽初始化中心。固定输入顺序与运行环境仍很重要；不应仅凭没有采样，就保证不同 GPU、库版本和平局处理下所有字节永远一致。

## 4. 每簇怎样变成一张 synthetic 卡片？

假设某簇包含 20 篇论文。

**数字特征。** 原始 20 行 X 求均值。例如只为说明计算，三行特征是 `[2,4]`、`[4,2]`、`[3,3]`，均值就是 `[3,3]`。真实代码用原始 X 求均值，不是将归一化后的 joint 中心直接当 synthetic X。

**文本选择。** 在 joint 空间找最靠近簇心的最多 5 篇；先追求它们对本簇主题的代表性，而不是最高语言模型新颖性分数。

**文本融合。** 默认约 320 字符在选中的文本间均分。5 篇时每篇最多取 64 字符，然后用空格拼起来。

这不是调用 LLM 改写，也不保证句子完整。加上空格后可能略超过 320 字符；每段还有最少 48 字符配额的逻辑，因此 320 不是所有调用场景的严格总长上限。

**重新编码。** 对拼接字符串重新运行 MiniLM，得到与保存文字绑定的 `text_emb`。

**mass。** 记录 20。这样后续知道此行代表多少源节点；但原文细节并不能从这一个数字恢复。

## 5. 三个阶段如何拼接：Cora 的完整预算算例

冻结设置中预算随累计数据增长，不是从头到尾固定 121 行。它大致按累计非 dev 源节点数的 5% 向下取整。

| 阶段 | 累计预算 | 本阶段操作 | 操作后 memory |
|---|---:|---|---:|
| stage 0 | 32 | 当前两类 delta 构造成 32 行 | 32 |
| stage 1 | 87 | 保留旧 32 行，新 delta 构造成 55 行 | 32＋55＝87 |
| stage 2 | 121 | 默认余量只有 34，但 3 个新类需总额度 45 | 旧保留 76＋新 45＝121 |

stage 2 要删旧 memory 的 11 行。按 mass 降序选前 76 行，再把被选中的索引恢复为原顺序；每条保留行内容不变。

删除可能发生在多个旧阶段，不保证每阶段平均删除，也不保证每个旧类覆盖不受损。因此“只追加”应完整读为：保留行不改写，容量不足时可以删除，再追加新块。

Citeseer 的 stage 2：总预算 143，旧 110 行，余量 33；两个新类的额度下限 30。于是保留 110，追加 33，不需要删行。

这两个配置已在 Gate3 runner 中落地；其 Cora 使用配置中的 `c_rule_new=45`，Citeseer使用不触发分支，并不是一个覆盖任意数据流的通用自动 c-rule 引擎。

## 6. 拼好节点后，边怎么来？

当前全 memory 的任意两条融合文本都算余弦相似度。k 个节点共有 `k(k−1)/2` 个无向候选对，选得分最高的约 `k×1.0` 对，再补反向边。

121 个节点时，候选无向对为 7260；通常选 121 对，存成 242 条有向边，GCN 归一化时再加入自环。

因此参数 `DEGREE=1.0` 不是“每点只有 1 个邻居”。若选满 121 条无向边，平均非自环度是 2，而且不同节点的度不均匀，有的可能没有非自环邻居。

项目常把它简称 text-kNN；严格实现是全局 top-E 文本相似边，不是每个节点各取固定个数近邻。

还有一个容易忽略的点：旧行 X/text 不变，但每阶段 topology 在全 memory 上重建，旧节点的邻居仍可能改变。保留旧数据内容不等于保证旧节点的 GCN 响应不变。

## 7. 最终 student 具体学什么？

每份 memory 先生成训练图，然后初始化新的两层 GCN、文本投影和温度参数。

每步训练：

1. 全 synthetic 图通过 GCN 消息传播；
2. 随机选最多 24 个根节点作为对比 batch；
3. 这些节点的图表示与其文本投影组成相似度矩阵；
4. 对角线是正确配对；
5. 图找文本、文本找图两个方向算交叉熵，再平均；
6. 更新 student 参数，不更新已构造好的小图。

这里“重新训练 student”与早期“ASM 的 outer 更新 X”彻底分开。最终方法构造阶段没有 ASM outer loop，但下游 student 仍正常用梯度训练。

mass 虽然以 `weights` 字段传给训练图，当前 `train_student` 没有读取它来加权或采样。各 synthetic row 被均匀抽样，不能说“一行 mass=20 等价于训练中重复出现 20 次”。

例如 121 roots 的训练步数是 `min(2048,16×121)=1936`；32 roots 是 512；143 roots 达到上限 2048。每步是一次 batch 更新，不是看完一遍图的一个 epoch。

## 8. 最后怎样去真实图上考试？

用已经训练好的 student，对真实图节点计算表示；再与类别 prompt 的文本表示比相似度，输出最像的类别。

后期代码在整张真实图上传播，所以计分节点可以接收无标签邻居信息；模型预测候选包含全部类别。只在指定 mask 和已到达类别上统计 current、old 与 cumulative。

这叫 transductive 评估，不是“完全没有见过测试节点任何信息”的严格 inductive 评估。也不同于早期 native 各阶段不相交的 whole-stage 推理。

## 9. 用一段伪代码收束最终算法

```text
输入：当前 delta、上一阶段 memory、当前总预算 B

计算新块总额度：max(预算余量, 15 × 新类数量)
如果需要：只删除低 mass 旧行，保留行不改写

对当前 delta：
    冻结 MiniLM 编码文本
    拼接归一化 X 与文本 embedding
    确定性 max-min 播种＋Lloyd 聚类
    每簇 X = 原始 X 均值
    每簇文本 = 最靠近簇心的最多 5 条原文截断拼接
    重新编码融合文本，保存 mass/stage/depth

拼接旧 memory 与新块
在全 memory 上用文本相似度选边
独立初始化 student，仅在 synthetic 图上训练
在真实图与类别 prompt 上评测
```

这是方法概念流程，不是可直接复制执行的程序。当前代码对两个数据集给出实验 runner；任意预算不足、空 delta、k≤0 等泛化边界仍需另行工程处理。

| 优化对象 | 在干什么 | 最终 frozen_v1 是否保留 |

# 第六部分：哪些可以下结论，哪些还不可以？

## 1. 当前证据较清楚地支持什么？

1. 在受控 native 协议里，小 compact 图具有独立 student 训练价值。
2. 已测 ASM 及保持约束不能稳定改善初始化；某个代理 loss 很低，不足以保证重训效果。
3. 打乱图文配对会降低表现，图文一一对应是实际有用的信息。
4. 确定性构造消除了一个重要的凝聚初始化随机来源。
5. 后期两个数据集的已测对照中，append 系在历史保持上强，累计表现有竞争力。
6. 新块容量和历史容量存在取舍，更多新行并不单调提高新类成绩。
7. frozen_v1 在项目报告的两数据集最终确认表中累计分数居首。

## 2. 不应该把它们扩大成什么说法？

- 不是“所有 ASM、CMI、图粗化或知识蒸馏都无效”。当前结论只覆盖已测实现与配置。
- 不是“只要用均值就保证可重训性”。均值是当前胜出的构造规则，不是泛化定理。
- 不是“所有 synthetic X 都与真实行不同”。单例簇、重复特征都可能让均值与真实行相同。
- 不是“融合文本等于高质量生成式摘要”。这里主要是摘录、截断、拼接。
- 不是“memory 不变就不遗忘”。全局语义边和重训模型会变化，旧阶段表现仍会变化。
- 不是“append 等于最优离线算法”。等价性只针对同构造器、同阶段划分、同配额的重放参照。
- 不是“compact 普遍强于 raw”。这里是特定图文训练协议下的观测，raw 仍可有更好的训练方法。
- 不是“6 个 student 就证明普遍稳定”。它们共享一份 memory；还需不同数据、阶段顺序和独立构造条件。
- 不是“5% roots 就严格是 5% 存储或训练成本”。文本、embedding、边和元数据都占空间，构造过程也有开销。
- 不是“test 节点完全未见”。后期协议允许无标签输入参与，且历史开发暴露需要审计。

## 3. 当前包的复现边界

本次对话前面的核查显示：native 单元测试 38 项通过，frozen 主文件哈希与冻结声明前缀一致。但单测主要覆盖早期 native 后端，不能替代 frozen 大型实验复现。

根 README 和 package manifest 主要记录 9 月 8 日状态；后续已增加 GraphCLIP/frozen 代码和 9 月 9 日文档，旧 manifest 尚未覆盖它们，且已有 native_core、文档索引与旧清单不一致。本文新建后也不将这些历史清单悄悄重签。

若以后要完整重跑最终方法，需要补齐服务器上的数据、MiniLM 权重、阶段 memory、最终逐 student 结果，并明确 scaled runner 与分区权限。不能只看一个 report 和 SHA 就宣称所有实验已字节级完整复现。

# 最后，用最少的话重新讲一次整个研究

最初，我们想复现 TAGSAM：把大论文图压成小图，让新模型用小图学习。先发现并修复官方评测、cache 和训练覆盖问题；修复后小图能训练，但 ASM 的效果不稳定。

为了知道原因，我们建立了可审计的 native 后端。静态对照显示，图文初始化的小图已经有用，继续 ASM 却不一定更好。随后把 ASM 变成 Append、Union 和 Protected-joint 等持续方法，发现重新整理旧 memory 不自动优于保留旧块。

通过固定旧 memory、替换新块、冻结旧 X、替换 centroid X、保存完整 outer 轨迹，逐渐排除了几个过于简单的解释。文本置换和无标签对齐诊断进一步支持：ASM 更新 X 时可能破坏固定图文配对。于是提出 Text-Anchored ASM，用附加约束保持这种配对。

但 Text-Anchored 的局部收益未稳定通过严格递归。继续诊断又发现：原 ASM 优化很弱，而更容易优化的 response-retention 即使 loss 大幅下降，也不能稳定让新 student 学得更好。

因此主线转向确定性构造：靠真实数据的聚类统计组织小图，不再依赖冻结模型响应反向改写 X。经过文本融合、拓扑、X 精炼和持续重聚类等消融，保留下来的是均值 X、几何近邻文本拼接、文本相似边，以及保留旧行内容的 append。

最后，用一个温和的新块容量规则处理保持与塑性的取舍，在 Citeseer 上检验迁移，再冻结版本做确认评估。当前方法不是“证明复杂方法永远没用”，而是：

> 在这个项目已验证的范围里，与其不断修改 synthetic 图去迎合一个代理模型，不如稳定地构造图文同源的小图，再用独立 student 的真实训练结果检验它。

这就是从复现 TAGSAM 一直走到 frozen_v1 的研究主线。
