## P2：静态 ASM 优化诊断（seeds 44–48 × outer_lr {0.01, 0.003, 0.001}）

### 核心问题：优化失败还是泛化失败？

**回答：优化失败（loss 几乎不降），且官方链路上同样成立。**

| 证据 | 数值 |
|---|---|
| native ASM loss 相对下降（100 outer steps，全部 15 个 run） | 仅 0.2%–1.2%（0.0460→0.0453 量级） |
| X 梯度范数 | 0.0002–0.0012，接近零 |
| 官方 master distill 500 步 syn_loss 相对下降 | 仅 ~4.7%（0.730→0.696） |

ASM 的 bi-level 梯度（经过 10 步 inner unroll 反传到 X）在两套实现上都几乎不产生有效下降。这不是 native 实现的 bug——官方代码的 loss 曲线同样平坦。

### 五 seed 下的结论

1. **outer=0 现象是 seed 依赖的，不是普遍规律**：5 个 seed 中 c44/c46/c47 几乎全部选 outer=0，但 c45 和 c48 在多个学习率下都选 outer>0 且有实际收益（c45 最高 +5.4 pp，c48 olr=.01 的 asm_dev 74.82 远超 frozen 49.92）；
2. **收益与 ASM loss 无关**：所有 run 的 loss 都几乎不动，但 student 结果差异很大——**ASM 更新对 student 的影响主要不是通过降低 matching loss，而是类似小幅随机/半随机扰动 X**。初始化差的 seed（c48 frozen 只有 49.9）被扰动改善的空间大，初始化好的 seed（c44/c47 frozen 75+）被扰动只会变差或不动；
3. **这解释了此前所有"不稳定"**：ASM 事实上接近一个 X 空间的弱扰动过程，其收益方向由初始化质量决定，因此跨 seed 方向必然不一致。

### Gate S 判定（PROTOCOL V2 §7）

按"≥4 seed dev 选择 outer>0 且 ≥ frozen"的标准：**当前 ASM 未通过 Gate S**（只有 2/5 seed 明确收益）。

含义：
- **方法形态应转向"构造式初始化为主 + 优化为辅"**：frozen 初始化质量是最强预测因子；优化只在初始化差时有修复价值；
- 下一步更有价值的优化方向不是调 ASM 超参，而是（a）提升初始化质量的稳定性（c46/c48 的 frozen 只有 50–58，找出为什么），（b）设计"仅在初始化差时介入"的自适应优化；
- P5 gate（response-retention）的解释框架也要调整：如果 λ_r 能让 loss 曲线真正下降（KL 项梯度不经过 inner unroll，梯度通路更直接），可能改变"优化失败"的格局——这是 gate 实验值得跑完的原因。

## P3：预算分配扫描（stage-2 总预算 94 行固定）

### 结果（累计 dev Macro-F1，2 students/arm）

| 分配（旧/新） | seed 44 cum | s44 s2(cur) | seed 45 cum | s45 s2(cur) |
|---|---:|---:|---:|---:|
| 67/27（现状） | **44.75** | **33.66** | 34.59 | 35.86 |
| 55/39 | 43.54 | 33.00 | 34.50 | 38.23 |
| 47/47 | 44.40 | 31.70 | 35.90 | 36.21 |
| 32/62 | 41.68 | 25.77 | **36.53** | **37.37** |

### 结论

1. **预算挤压不是稳定主因**：给新类更多行数没有稳定提高当前阶段指标（seed 44 反而单调变差）；
2. **方向再次由 seed 决定**：seed 44 偏好保旧（67/27 最优），seed 45 偏好让新（32/62 最优）——与 P2 的"初始化质量决定方向"一致：seed 45 的旧 memory 较差（s1 只有 42.96），压缩它损失小、腾给新类收益大；seed 44 的旧 memory 好，压缩即受损；
3. **可操作的推论**：固定分配比不是正确设计；**基于旧 memory 质量诊断的自适应分配**（如按旧 memory 的 dev 响应决定收缩量）才可能跨 seed 稳定。这可以成为方法的一个组成部分，且它是构造式的（不依赖 ASM 优化），与 P2 结论方向一致；
4. 预算挤压被排除为"持续损失的主要独立解释"——此前 old+全量raw(47.39) vs old+compact(42.98) 的差距更多来自 27 行 compact 的信息容量，而不是行数分配错误。
