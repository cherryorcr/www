# R6 机制诊断的数值复现修订

本修订发生在机制实验任何 report student 评分之前。独立确认批次已经完成，配方及产物不修改。

最初机制准备在 Cora/Citeseer 的 `parent_000` 与历史 R5 `joint` 的逐字节一致检查处停止。没有输出选择封条或 report 评分。失败目录保留为 `results/tgc_r6_mechanisms_20260923`。

单独诊断复跑原版 `J.construct` 与新包装器，并核对父图、当前 delta、初始化 seed 和 minibatch hash。Cora 的 C0 append 基图逐字节相同，teacher 首步损失及 minibatch hash 相同，但 GPU 重训末端状态不相同；同一进程调用原版与包装器也会产生微小变化。重新生成的软分配最大元素变化可达约 0.0113，X 最大变化约 0.000484，并可改变文本排序。不能将这些变化简单当成逐字节复现，也不能把新产物直接复用历史分数。

执行修正：

1. 算法、teacher seed、优化步数、预算、student 和机制候选不变，不根据确认分数调整参数。
2. `parent_000/111` 为本次重新生成的端点，所有下游 student 重新评分；所有反事实均引用本批对应端点/teacher/assignment。
3. 新增 `frozen_joint`、`frozen_recursive` 两个完全复制历史 R5 memory 的控制臂，测量当前端点的重构数值敏感性。逐项记录 X、mass、文本、边的差异。混合父状态仍使用封存的 R5 s1 memory。
4. s1 三臂、s2 二十三臂、四个数据集/顺序条件、六 report seeds，共 624 个槽位。全部候选先生成，再封存，再训练，禁止按接近历史或按分数挑选构造重复。
5. 使用新目录和新代码快照 `tgc_r6_mechanisms_20260923b`。保留失败版、诊断 JSON 和版本指纹。独立重载审计继续执行，并补支持图、文本来源、双精度投影与加权传播算子的只读审计。

机制对照由此识别的是固定配方、本次已封存构造产物下的效应。仅有六个 student seeds 仍不足以量化构造随机性；数值波动与较小机制收益同量级时必须保留结论。后续若优化数值协议，需要所有方法共用并重新验证，不能默默替换本批 student。
