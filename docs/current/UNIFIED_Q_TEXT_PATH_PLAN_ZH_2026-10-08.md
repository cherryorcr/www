# In-loop CaT-Q 文本路径诊断与单一修改预注册

本轮遵循用户确认：先诊断，再选择一个修改方向，最后同协议独立确认。已有负结果保留；不修改历史目录，不删除数据，不提交 Git。所有分类结果仍使用 report-dev，封存 test 不读。

## 第一阶段：只观察

- 当前 `uq_dm_edgefree` 结构、30 步优化、5% 残差界、冻结旧前缀、edge-free、top-1 原文、320 字符不变。
- WikiCS、SportsFit、BookHis；参考顺序 9101；构造种子 271006；完整五阶段。诊断不训练下游 Student，不据分类成绩决定修改。
- 在第 0、中间、末次更新前记录：DM/GM/传播对 Q logits 的梯度；总外层 GM 经 `text_new` 返回 Q 的直接路径；范数比与夹角。直接文本路径不是可与其他消融差值线性相加的独立损失。
- 每步记录硬文本来源切换。记录按类等权的软硬余弦差、Q 加权文本重构失真、唯一来源比例及同类最近 payload 覆盖。
- 诊断比较 `argmax(Q)` 与同类 Q 加权文本 medoid，后者只用于机制测量；它在此目标下最优，不意味着分类更好。特别检查重复来源与覆盖损失。
- callback 默认关闭，保存/恢复 RNG，只用 `autograd.grad`，不改 `.grad`。CPU 单元测试和 WikiCS GPU 开关配对核对 X、文本来源及 RNG。

## 第二阶段：诊断后才冻结一个候选

GPU smoke 补充：两步 WikiCS 的开关对照来源相同，但 X 最大差约 4.05e-5，未满足最初逐位附近阈值。CPU 测试保持逐位一致。保留失败记录，新增 off/off 对照量化既有 GPU 漂移；相对漂移超过 1e-3 或来源改变则中止。是否落在 off/off 波动包络单独记录，不能把放宽阈值当作逐位一致证明。

优先考虑硬材料化目标不一致。只有在量化失真明显且覆盖没有被系统性破坏时，才测试对应的单一硬投影修改，并同时用于每步训练前向与最后保存。若诊断主要指向缺少节点级目标，再单独设计图文联合统计目标。本轮不同时加入两者，不加 EM、拓扑、旧记忆刷新或多架构构造代理。

### 已选择候选，尚未查看其下游成绩

三图五阶段诊断完成。Q 加权文本 medoid 相比 argmax(Q) 降低失真，三图平均语义覆盖均更好；但唯一来源比例降低，WikiCS 约 46%，这是必须保留的风险，不额外加去重或动态参数。文本直接梯度与 DM 的范数比存在显著数据集差异，不能统一归因为文本梯度缺失或一律增大其系数。

因此本轮只修改 `text_materialization=q_text_medoid`：对每个 slot，在当前 delta 同类真实原文中最小化 Q 加权余弦失真。等价于选择最接近 Q 加权文本中心的真实原文。每步硬前向和最终保存使用同一选择函数，ST 软反向不变。Q、残差、GM/DM/传播目标、所有权重与优化器保持不变。该投影的失真最小性不意味着分类最优；只做这一候选，不同时测试联合统计损失。

迁移 readout 固定为 SGC(K=2)：两跳规范化传播后单个线性图映射，无 GCN 的两层非线性；文本投影、prompt 分类、损失、步数与 batch 均沿用原 Student。原 GCN 默认数学实现保持不变，并有默认 factory 的逐位一致测试。

## 第三阶段：独立确认范围

计划采用三个数据集、两个新的类别顺序 9201/9202、两个独立构造种子 271108/271109；这些与诊断和历史 9101/9102/9103 分离。固定参考 memory 预算轨迹、类别组大小、输入划分、文本编码器、Student seeds 150/151/152 和 2048 步。

对照为原主方法、诊断选定的单一候选、CaT-nearest5、GECC-hard TAG。前两个是方法/组件比较，后两个才是公开论文机制适配。三图全部保留，不按数据集挑变体。

优先做完整五阶段闭环构造，最终 memory 在原 Prompt-GCN 和另一个真正不同的图编码器上评估，不针对 readout 重新凝聚。分类目标、文本分支、训练预算和 prompts 固定。报告 Final F1/Accuracy/Old/New、同 cell 配对差、最差 cell、正收益比例、构造时间/显存、memory hash 和实际存储。此阶段若仅评估最终 memory，不虚构 stage-average 或 worst-stage。

这是有限规模独立确认，不冒充完整 3-5 顺序/3-5 构造种子的投稿主表。不得用 Student seeds 当作独立构造样本；共享顺序/种子的相关性在区间解释中明确。已有可复现数值风险保留，不能用有利重复覆盖原值。

### 预算可行性修订，保留原计划和失败记录

BookHis/9201 在第 3 阶段只有 659 个 raw 节点，却要求新增 828 个 slot；它在构造任何方法、计算任何分类成绩前被统一配额检查拒绝。此固定预算轨迹来自历史参考顺序，并非每阶段按当前到达量重算 5%。

现按纯计数规则：从 9201 起递增扫描，取各数据集前两个满足每阶段 `类别数 <= 新增 slot <= 当前 raw 数` 的顺序。预检不训练 Student、不读取结果分数。WikiCS/SportsFit 为 9201/9202；BookHis 为 9202/9203。构造种子仍为 271108/271109，其他配置不变。完整计数、拒绝原因及预检脚本 hash 见 `order_feasibility.json`。

本轮结论限定于可行的 fixed-schedule 顺序，不能宣称覆盖任意自然到达流。后续真实 fixed-rate 验证应单独进行，而不是将这次预算可行性筛选藏起来。
