# v2 LLM 文本融合完整管线结果（含 student 训练）

日期：2026-09-09
数据：服务器 `problem_validation_results/v2_full_2026_09_09/`（本地镜像 `results_v2_full.json`）
LLM：本地 Qwen3-32B-AWQ（vLLM 0.19.0，双 RTX 4090 tensor-parallel，temperature=0，thinking 禁用，英文提示词，8 线程并行）。135 簇融合 100% 成功（50w 版 144s，100w 版 254s），LLM 基础设施完全可靠。
协议：与 frozen_v1 GraphCLIP gate 完全一致（Cora k=135、确定性聚类、簇均值合成X、文本kNN deg=1.0、6 students × 2048 步、dev-only）。

## 2. 判定：LLM 融合未通过 gate，v1 保持为冻结方法

同字节预算下 LLM 融合稳定劣于截断拼接（0/6 配对全负），v2 不并入方法。

## 3. 三条独立发现（比单一判定更有价值）

### 发现1：文本长度本身有害，且主导了一切

concat_320→concat_700：同样的拼接方式，只是变长，**−10.8**。这是本轮最大的效应量。机制：MiniLM 均值池化下，长文本的 embedding 更接近"泛化主题均值"，簇间 embedding 相似度上升 → 对比学习的负例区分度下降 + 文本kNN拓扑质量下降。**短文本的"锐利性"是这个管线的关键资源。**

### 发现2：LLM 质量收益真实存在——但方向被证明在"同长度下更好"，不是"更好所以能更长"

同为 ~92KB 文本，llm_100w 比 concat_700 高 **+4.74（5/6）**：当文本必须长时，LLM 的语义组织确实优于机械拼接。且 llm_100w 的 std=1.51 是全场最低——LLM 文本让 student 训练更稳定。**LLM 融合不是没用，是用错了预算点。**

### 发现3：为什么同预算下 LLM 输给拼接？（与 Gate S2 det-CMI 失败同构）

拼接保留的是**原文的字面锐利片段**（真实标题、独特术语原样出现），MiniLM 对这些片段产生高判别度 embedding；LLM 摘要是**平滑的学术语言**（"This paper explores various approaches to..."），135 条摘要共享大量模板句式，embedding 空间被系统性拉近。用一句话说：

> **对 embedding 级别的对比学习下游，文本的"判别性"比"可读性/信息组织"更重要；LLM 优化的是后者，恰好损害前者。**

这是继 Gate S2（CMI 选择、粗化拓扑、一阶精炼全部降级）之后，第四个"更智能的加工在此管线中失效"的实例，且机制一致：加工目标（语义质量）与下游真正消费的量（embedding 判别度）错位。

## 4. 论文可用的表述

1. **主方法不变**：frozen_v1 的截断拼接融合保持冻结；
2. **消融章节新增**：LLM 生成式融合的受控对照（4 arm、长度配平设计、6 students 配对），结论为"同预算下 LLM 摘要的语言平滑性降低 embedding 判别度"；同长度下 +4.7 的正向对照保留，说明失败不在 LLM 能力而在预算-判别度 trade-off；
3. **观察升级**："构造式方法中文本的价值 = 字面判别性 × 语义覆盖，两者在固定字节预算下此消彼长；机械截断意外地站在了判别性最优的一端"；
4. Future work：判别性感知的 LLM 提示（要求保留原文关键短语/禁止模板句式）、或对 LLM 文本做去模板后处理——有 llm_100w 的 +4.7 打底，这个方向不是空想。

## 6. 边界

- 单数据集（Cora）、单预算点、dev-only；
- 只测了一种提示词模板与一个 LLM；判别性感知提示未测；
- MiniLM-tiny 文本塔可能放大"模板句式相似"问题，更强文本塔下结论可能不同（记为限制）。
