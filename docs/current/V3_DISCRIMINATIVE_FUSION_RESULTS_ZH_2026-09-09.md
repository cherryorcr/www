# v3 判别性感知 LLM 融合结果（方向A第二轮）

日期：2026-09-09
数据：服务器 `problem_validation_results/v3_disc_2026_09_09/`
设计：针对 v2 失败机制（"LLM 平滑性损害 embedding 判别性"）的四种修复，全部同预算配平（~340 字符），含 `mean_pairwise_cos` 判别性审计指标（135 条融合文本 embedding 的平均两两余弦，越低=越判别）。
LLM：本地 Qwen3-32B-AWQ（vLLM，no-think）。协议与此前 gate 一致。

## 1. 结果

| arm | 修复策略 | dev F1 | std | pairwise cos |
|---|---|---:|---:|---:|
| **v1_concat（基线）** | 截断拼接 | **54.17** | 4.30 | 0.2195 |
| concat_kw | 拼接240字符+LLM关键词100字符 | 51.76 | 3.51 | 0.2354 |
| disc_prompt | 判别性提示（强制verbatim术语、禁模板句式） | 47.45 | 1.88 | **0.2186** |
| best_of_n | 4变体生成+embedding判别度选择 | 43.49 | 2.17 | **0.1686** |
| keyword_bag | LLM抽15-20个verbatim术语列表 | 42.75 | 3.56 | 0.3192 |

## 2. 判定：四种修复全部未超过基线，方向A关闭

v1 截断拼接经受住了第二轮攻击。LLM 文本融合（原始版+判别性感知版共 6 种变体）在同预算下全部劣于机械拼接。

## 3. 最重要的发现：判别性代理假设被证伪

**pairwise cosine 与 dev F1 几乎无关，甚至反向**：

- best_of_n 拿到了全场最低的 pairwise cos（0.1686，比基线判别 23%）——但 F1 只有 43.5，倒数第二；
- disc_prompt 的 cos 与基线几乎相同（0.2186 vs 0.2195）——F1 却低 6.7；
- keyword_bag 的 cos 最高（0.3192）却不是最差的 F1。

这推翻了我在 v2 分析中提出的机制假设（"LLM 失败是因为 embedding 判别性下降"）。**簇间 embedding 分离度不是可重训性的正确代理**——你可以把 135 条文本的 embedding 推得彼此很远（best_of_n 做到了），student 照样学不好。

### 修正后的机制解释

真正起作用的量不是"融合文本彼此多不同"，而是**"融合文本的 embedding 与它所代表的真实节点文本的 embedding 分布是否同构"**：

- 拼接文本 = 真实文本片段的字面拼合，其 embedding 天然落在成员 embedding 的凸包附近 → student 在小图上学到的 graph-text 对齐可以直接迁移到真实图的 zero-shot 分类（真实节点文本和类 prompt 都在同一分布里）；
- LLM 文本（无论平滑版还是判别版）是**分布外的新文本**，它的 embedding 系统性偏离真实文本流形 → student 对齐的是一个"合成文本空间"，评测时真实节点文本回不到这个空间；
- best_of_n 主动最大化簇间分离，恰恰把文本推得离真实流形更远——判别性上去了，迁移性崩了。

一句话总结（这条比原假设更深刻）：

> **凝聚文本的价值不在自身判别性，而在与评测分布的同构性。任何生成式改写——不管以何种目标——都是分布迁移，而截断拼接是唯一保证零分布迁移的融合方式。**

这与整个项目的主叙事完美闭环：ASM 改 X 失败（离开数据分布）、响应约束失败（对齐冻结模型而非数据）、再聚类失败（重组破坏统计）、LLM 改文本失败（离开文本分布）——**四个模态上的同一条定律：合成物越贴近真实数据统计，可重训性越好**。

## 4. 有价值的次级观察

1. **concat_kw 是最接近的挑战者**（51.76，−2.4）：保留 240 字符原文的部分几乎守住了下限，说明"原文占比"与性能单调相关——进一步佐证分布同构解释；
2. **所有 LLM arm 的 std 都低于基线**（1.9–3.6 vs 4.3）：LLM 文本让训练更稳定但天花板更低——一个真实的 stability-performance trade-off，论文可报告；
3. `mean_pairwise_cos` 审计指标本身是有用的工具产出——它证伪了一个直觉代理，这类"代理指标失效"的证据在图凝聚文献中很少见。

## 5. 方向A最终结论（论文表述）

- 方法保持 frozen_v1 截断拼接不变；
- 消融章节完整呈现两轮共 9 个 LLM 变体（v2 的 4 个 + v3 的 5 个）的受控失败，配对分解与判别性审计齐全；
- 核心 claim 升级为："**在 embedding 消费型下游中，文本融合的首要约束是与评测文本分布同构；生成式改写不论目标如何都引入分布迁移**"——由 pairwise-cos 反例（best_of_n：判别性最优、性能倒数）提供直接证据；
- Future work 收窄为唯一还站得住的方向：**抽取式 LLM 融合**——让 LLM 只做"选哪些原文片段拼接"的决策（输出必须是原文子串，可验证），不做任何改写。concat_kw 的 51.8 提示该方向上限可能接近但难以超越简单拼接，故优先级降为低。

## 6. 成本记录

v3 全程本地 LLM：disc_prompt 136s、keyword_bag 192s、concat_kw 184s、best_of_n 491s（4×135=540 次生成）。零 API 成本，全部可复现（t=0 的 arm 确定性；best_of_n 的 t=0.7 变体有采样随机性，选择步确定性——协议中已注明）。
